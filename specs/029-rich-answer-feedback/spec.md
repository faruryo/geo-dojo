# Feature Specification: クイズ解答時のリッチフィードバック演出と補足情報表示

**Feature Branch**: `029-rich-answer-feedback`  
**Created**: 2026-09-18  
**Updated**: 2026-09-19（375px実機プロトタイプ検証反映: 帯お題据え置き・idle高さ完全固定、カード情報集約、同名多県全県併記、帯タップ状態遷移、連続正解グラデーション演出）  
**Status**: Draft  
**Input**: User description: "正解時の一瞬の表示をもうちょっとリッチにすることを考えようか。正解の地図の位置も重要だけど、補足情報も重要。あと、音と効果的なおめでとう的な表示も欲しい。まずはこういう時にどういう表示にしたら良いか。"  
**Related**: `specs/027-map-quiz-hud`（HUD不変条件）、`specs/008-quiz-difficulty-display`（難易度表示）

## 前提・背景

現在 geo-dojo のクイズ解答後フィードバックは、短い時間（保存時間 + 最短1.2〜1.5秒）で単純なテキスト（`✓ 正解！` / `✗ 不正解` と自治体名・県名）とシンプルな Oscillator 2音が表示されるのみとなっている。
また、全画面HUD化したモード（モードA・D、および地図混在セッションのB・C）では難易度バッジが省略されており、解答時に難易度や人口などの豆知識を得る機会がない。

本機能では、DuolingoやGeoGuessr等の先行事例を参考に、**「正解した瞬間の達成感（音・演出）」**と**「地理知識を深める補足情報（難易度・人口・位置）」**を両立させ、学習体験の質と継続動機を向上させる。

### HUD不変条件の厳守・帯のidle高さ完全固定とフローティング化の決定（2026-09-19）
`specs/027-map-quiz-hud` では、下部HUD（`BottomHud`）の高さ変動が地図コンテナの伸縮、拡大率・中心位置のズレ、Googleロゴや自動フォーカスの計算矩形破壊を引き起こすことを防ぐため、帯高さを固定する不変条件を定めている。

375px 実機プロトタイプ検証において、上部フローティングカードと下部帯の両方に自治体名を表示すると、実機幅で上下に同一文字列が並んで視覚的に冗長となることが判明した。
元々出題中のお題に読み仮名は表示されていないため（`immersive-quiz-view.tsx` の `singleTitle` / `modeAContent`。読み仮名はフィードバック時に初めて提示）、**下部HUD（`BottomHud`）はフィードバック中もお題表示（prompt）のまま据え置き、上部フローティングカード側に「答え」（正否・自治体名・よみがな・難易度・人口）を集約**する。

これにより、下部HUDは解答瞬間の 56px への伸長（4〜12px の伸び）が完全に不要となり、**出題中（idle）の高さ（通常 44px / Mode A 52px）のまま完全固定**される。地図コンテナのリサイズが完全にゼロ（0px）となり、027 の不変条件がさらに強固に保証される（`BOTTOM_BAND_FEEDBACK_PX` は廃止）。

| モード | 帯（お題・据え置き） | カードで新しく出るもの |
|---|---|---|
| A | 池田町 | 正解の県（県ごとのよみがな・人口）・難易度 |
| B | 館山市 | 千葉県・よみがな・難易度・人口 |
| C | 千葉県 | 館山市・よみがな・難易度・人口 |
| D | 館山市（千葉県） | よみがな・難易度・人口 |

#### Mode A における上部カードと地図の重なり・対話設計
Mode A は日本全図（固定倍率）のため、北海道・東北正解時には上寄せカードと地理的表示領域が近接・重複し得る。
これに対し、カードは `pointer-events: auto` とし、**カード領域自体のタップで「即時スキップ」**できるようにする。一方、カード外の地図面タップはスキップではなく地図操作（パン・ズーム）として保護する。またカードの高さを通常時約 68px に抑えることで、日本全図の北方領域の隠蔽を最小限に留める。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 解答時の補足情報表示（難易度・人口・地理ファクト） (Priority: P1)

学習者が問題を解答（正解または不正解）した際、その市区町村の難易度（★1 入門〜★4 達人）や人口データ（例: 約12.5万人）などの補足情報がフローティングカード（HUD経路）または問題カード内（カード経路）に表示され、地域の規模感や学習の納得感を得られる。

**Why this priority**: 正誤に関わらず「この自治体はどのくらいの規模・難易度なのか」を知ることは地理学習の中核価値であり、データも既存マスタに存在するため最小リスクで価値を提供できる。

**Independent Test**: モードA・B・C・D、カード経路・HUD経路のそれぞれで解答した際、補足情報（難易度・人口）が正しい単位（政令市の合算など）で表示されること。

**Acceptance Scenarios**:
1. **Given** HUD経路（モードA/D、または地図混在セッション）, **When** 解答する, **Then** `TopHud` 直下に不透明（`bg-[#111111]`）のフローティングカードが現れ、正否（「🎉 正解！」「✗ 不正解」等）、自治体名、よみがな、難易度（`☆ 入門`〜`☆☆☆☆ 達人`）、人口（「約○.○万人」）が表示される。下部帯（`BottomHud`）はお題表示のまま据え置かれる。
2. **Given** カード経路（4択単独セッションのモードB/C）, **When** 解答する, **Then** 問題カード内に難易度バッジに加えて人口情報が表示される。
3. **Given** 政令指定都市（例: 大阪市）が出題されたモードB/CまたはモードA, **When** 解答する, **Then** 1区のみの人口ではなく、同一市内の区人口を合算した「市の総人口（例: 約275万人）」が表示される。
4. **Given** モードD（5桁コード単位の出題）, **When** 解答する, **Then** 出題対象となった自治体（政令市の場合は当該区）自身の人口が表示される。
5. **Given** モードAで同名異県の市区町村（例: 伊達市＝北海道・福島県）, **When** 解答する, **Then** 合算ではなく県ごとの内訳（例: `北海道: 約3.3万人 / 福島県: 約5.8万人`）として併記され、難易度は代表難易度（最も難しい方）が表示される。
6. **Given** モードAで3県以上の同名市町村（例: 池田町＝4県）, **When** 解答する, **Then** 要約（他○県）で落とさずに全県の内訳（県名・よみがな・人口）がカード高さ上限（112px）内でスクロールなしに収まる。
7. **Given** 不正解となった場合, **When** フィードバックを見る, **Then** 正解時と同様に正解自治体の補足情報が表示され、復習の手がかりが得られる（下部帯はお題のまま据え置き）。

### User Story 2 - テンポと閲覧の両立（進行UX・スキップ操作） (Priority: P2)

学習者が補足情報や地図の位置を自分のペースで確認できるよう、フィードバック時間の最適化と手動スキップ機能を提供する。

**Why this priority**: 補足情報を追加してもすぐに画面が切り替わっては読めず、逆に長すぎると反復学習のテンポを阻害するため。

**Independent Test**: フィードバック表示中に、指定のスキップ領域タップまたはSpace/Enterキーを押すと即座に次の問題へ進むこと。何もしなくても保存完了後一律 2.0秒で自然に進むこと。地図のパン・ズーム操作で誤スキップしないこと。

**Acceptance Scenarios**:
1. **Given** フィードバック表示中（保存Server Actionが完了済み）, **When** `BottomHud` 領域（出題中の「お題再表示」から「スキップ」に切り替わる）またはフローティングカード本体をタップ、あるいはSpace/Enterキーを押す, **Then** 残り待機時間を待たずに即座に次の問題へ遷移する。
2. **Given** フィードバック表示中, **When** 地図面をドラッグしてパンしたりピンチズームしたり、あるいは `TopHud` のボタン（離脱・ミュート）を操作する, **Then** 次問へのスキップは発火せず、地図の確認やHUD操作が正常に行える。
3. **Given** 保存Server Actionの通信中（まだタイマーが張られていない間）, **When** スキップ入力（指定領域タップ/キー）が行われた, **Then** スキップ要求が保留され、保存完了と同時に遅延ゼロで即座に次問へ遷移する（入力が無視されない）。
4. **Given** モードAでSpaceキーを長押し（キーリピート）している, **When** 解答確定からフィードバックへ遷移した, **Then** 確定時のキーリピートでスキップが誤作動せず、一度キーを離して再度押すまでスキップを受け付けない。
5. **Given** 次問へ切り替わった直後（250ms以内）, **When** 画面上の任意の位置（地図タップ・選択肢ボタン等）を連打・誤タップした, **Then** 全モード共通で入力を無視する誤タップガードが作動し、次問の誤解答が暴発しない。
6. **Given** 何も操作しない, **When** 保存完了後、規定の待機時間（一律 2.0秒）が経過する, **Then** 自動的に次の問題へ遷移する。

### User Story 3 - 達成感を高める正解演出（段階制の音・演出とおめでとう表示） (Priority: P3)

学習者が正解した際、連続正解数に応じた心地よい和音チャイム（SE）やステップアップする称賛メッセージ（「正解！」→「いいね！」→「お見事！」→「すごい！」、「n連続」チップ）、正解ポリゴンの発光演出、および5連続達成時の紙吹雪演出が表示され、反復学習でも飽きずに達成感を実感できる。

**Why this priority**: 基本的な学習価値（US1・US2）が確立した上で、学習体験をさらに楽しく魅力的にするためのエンハンスメントであるため。毎問一律のフル演出ではなく段階（グラデーション）を設けることで、反復学習における演出のマンネリ化を防ぎ継続モチベーションを高める。

**Independent Test**: 正解した際、連続正解数に応じてピッチが上がる和音SEが鳴り、称賛ラベルのステップアップアニメーション、地図ポリゴンの発光（Pulse）、および5連続時のCSS紙吹雪が確認できること。

**Acceptance Scenarios**:
1. **Given** クイズで正解した, **When** 音声ミュートが無効である, **Then** 従来の単音（ピピッ）ではなく、心地よい和音（メジャーコード調、合計再生時間 0.35秒以内）が再生される。連続正解数に応じて和音のピッチが全音ずつ上昇する（1〜4問目、最大4段階）。連続正解時も音が重なって濁らない。
2. **Given** クイズで正解した, **When** フィードバックが表示される, **Then** 称賛ラベルが連続正解数に応じてステップアップ（1問正解:「正解！」、2連続:「いいね！」、3連続:「お見事！」、4連続:「すごい！」）し、2連続以降はカード内に「n連続」チップが表示される。称賛ラベルにはバウンスアニメーション（`transform: scale`）が適用される。
3. **Given** 5連続正解を達成した, **When** フィードバックが表示される, **Then** 画面上にCSSアニメーションによる紙吹雪（44粒、外部ライブラリ不使用）が舞い、オクターブ上のトーンを加えたファンファーレ和音SE（0.34秒）が再生される。
4. **Given** 地図クイズ（モードA/D）で正解した, **When** 画面を見る, **Then** 既存の正解ハイライト（緑色塗りつぶし）に加えて、ポリゴンが一瞬パッと光る（Pulse / Glow）アニメーションが適用される（モードAの同名異県では全正解県が光る）。
5. **Given** 端末の `prefers-reduced-motion: reduce` が有効, **When** 正解する, **Then** 紙吹雪・バウンス・パルス等の動きを伴うアニメーションは無効化され、静的な表示（またはフェードインのみ）となる。
6. **Given** スクリーンリーダー等の支援技術を使用中, **When** 解答する, **Then** `aria-live="polite"` を通じて「正解！ 3連続！ ○○、よみがな、難易度: ○○、人口: 約○万人」と一連の補足情報が重複なく通知される。

## Edge Cases

- **人口データが未設定（null）の市区町村**:
  - `population` が null または 0 の場合、人口表示行を省略し、難易度や名称のレイアウトを崩さない。
  - 政令指定都市の区合算において、所属区のいずれか1つでも `population` が欠損（null または 0）している場合は、不完全な合算値を表示せず市人口全体を非表示（人口行を省略）とする。
- **音声ミュート時の挙動**:
  - `isSoundMuted() === true` の場合、SEは再生されず、視覚フィードバックのみが実行される。
- **モバイル375px幅でのフローティングカードのサイズ**:
  - 画面幅 375px において、カード幅は最大 340px（左右マージン約 17.5px）。通常時の高さは 68px 程度。
  - 同名多県（池田町・4県など）の場合も最大高さは 112px に制限し、全4県の内訳（県名・よみがな・人口）を要約で落とすことなくスクロールバーを出さずに収める（地図を過度に覆わない）。
- **不正解時の表示**:
  - 不正解時にも同様のフローティングカードで正解自治体の名称・よみがな・難易度・人口を表示するが、称賛演出（和音チャイム・バウンス・おめでとうテキスト・連続チップ・紙吹雪）は行わず、既存の不正解SE（ブブー）と「✗ 不正解」表示を維持する。下部帯はお題表示のまま据え置かれる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、全出題モード（A・B・C・D）および復習クイズにおいて、解答フィードバック表示時に正解市区町村の「難易度」（`DIFFICULTY_LABEL` 準拠: `☆ 入門` 〜 `☆☆☆☆ 達人`）を表示しなければならない。
- **FR-002 (人口の表示単位と合算)**:
  - **FR-002a**: モードB・C、およびモードAにおいて同一県内に複数区を持つ政令指定都市を出題する場合、当該市に属する全区の `population` を合算した「市の総人口」を表示しなければならない（全区のデータが存在する場合に限る。一部欠損時は市人口表示を省略）。
  - **FR-002b**: モードD（5桁コード単位の出題）においては、出題対象となった自治体（政令市の場合は当該区）自身の `population` を表示しなければならない。
  - **FR-002c**: モードAにおいて複数県に存在する同名市町村（例: 伊達市、池田町）の場合、合算せず県ごとの内訳（県名・よみがな・人口）として併記しなければならない。最多4県（池田町）の場合も含め、カード上限高（112px）内に全県の内訳をスクロールなしで収めなければならない。
  - **FR-002d**: 人口の表記形式は、以下のルールに厳格に従わなければならない:
    - 10,000人以上: 小数第2位を四捨五入し「約○.○万人」と表記する（100万人以上も同一基準で「約○○○.○万人」と表記。例: 横浜市「約377.7万人」、大阪市「約275.4万人」）。
    - 10,000人未満: 1の位までカンマ区切りで「約○,○○○人」と表記する（例: 「約6,320人」）。
- **FR-003**: HUD経路における補足情報表示は、`BottomHud` の帯高さを出題中（idle）の高さ（通常 44px / Mode A 52px）のまま変更せず完全固定し、`TopHud` 直下のステージ領域に重ねる**不透明フローティングカード（`bg-[#111111]`）**として描画しなければならない。カード幅は最大 340px、通常時高さ約 68px、最大高さ 112px（多県時）とし、スクロールバーを発生させてはならない。カード領域は `pointer-events: auto` とする。
- **FR-004 (進行制御とスキップ)**:
  - **FR-004a**: システムは、`BottomHud` 領域のタップ操作について状態に応じた振る舞いを明確に分離しなければならない:
    - 出題中（回答受付中）: お題の再表示（`onRequestIntro`）を発火する。
    - 解答フィードバック表示中: 次問への即時スキップを発火する。
    なお、フィードバック中における他のスキップトリガーは「フローティングカード本体のタップ」「キーボード操作（Space/Enter）」とし、地図面のドラッグ・ズーム操作および `TopHud` 内の操作ボタン押下はスキップ発火から除外しなければならない。
  - **FR-004b**: 保存Server Actionの待機中にスキップ要求があった場合、フラグを保留し、保存完了と同時に待機時間ゼロで遷移しなければならない。
  - **FR-004c**: キーボードのSpace/Enterの `event.repeat` を無視し、keyup を挟むまでスキップ入力を受け付けてはならない。
  - **FR-004d**: 全出題モードにおいて、次問へ切り替わった直後 250ms 間はすべての回答入力（地図タップ・選択肢クリック）を無視する誤タップガードを設けなければならない。
  - **FR-004e**: スキップ操作が行われない場合、保存完了後、全モード一律 2.0秒 の待機時間を経て自動的に次問へ遷移しなければならない。
- **FR-005 (正解SEと連続演出)**:
  - **FR-005a**: 正解時の和音SEは、連続正解数に応じて全音ずつピッチを上昇（1〜4問目、最大4段階）させなければならない（合計再生時間は各 0.35秒以内）。
  - **FR-005b**: 5連続正解時には、オクターブ上のトーンを加えたファンファーレ和音SE（0.34秒）を再生しなければならない。
- **FR-006 (視覚演出の段階制とアクセシビリティ)**:
  - **FR-006a**: 称賛メッセージは連続正解数に応じて段階的にステップアップ（「正解！」→「いいね！」→「お見事！」→「すごい！」等）し、2連続以降はカード内に「n連続」バッジ／チップを表示しなければならない。
  - **FR-006b**: 5連続正解時には、画面上にCSSアニメーションによる紙吹雪演出（44粒、外部ライブラリ不使用）を表示しなければならない。
  - **FR-006c**: 地図クイズ（A/D）の既存正解ハイライトに対する発光（パルス）アニメーション、および称賛ラベルのバウンスアニメーションを提供しなければならない。
  - **FR-006d**: `prefers-reduced-motion: reduce` が有効な環境では、紙吹雪、バウンス、パルスの動きを伴うアニメーションを無効化しなければならない。
  - **FR-006e**: 解答フィードバック表示時、支援技術向けに `aria-live="polite"` を通じて正否、連続正解数、自治体名、よみがな、難易度、人口の案内を重複なく提供しなければならない。

## Key Entities

- **Municipality**: 市区町村データモデル。`lib/quiz/municipality-data.ts` の型定義に `population?: number` プロパティを正式に追加する。
- **FeedbackCard**: HUD経路においてステージ上部に表示される一時的なフローティング情報カード。

## Assumptions

- `app/(app)/quiz/municipality/actions.ts` の `getMunicipalityMaster()` は `db.select().from(municipalityMaster)` を実行しており、**`population` を含む全列を既に取得している**。
- `app/(app)/quiz/municipality/[mode]/page.tsx:161-171`（通常クイズ）および `app/(app)/quiz/review/page.tsx:40-50`（復習クイズ）の両方のマッピングにおいて `population: m.population ?? undefined` を追加することで、新規クエリやDBスキーマ変更なしに全経路で人口データを利用可能である。
- 政令市の区と親市の紐付けは、マスタの `(name, prefecture)` が一致するレコード群からメモリ上でO(N)で合算可能である。
- 連続正解数は既存のクイズ状態（`state.results`）から導出可能であり、新規の永続化状態やDBカラムを必要としない。
- セッション完了時の演出（`completionSeEvent` による `perfect` / `complete` の出し分け）は既存結果画面の責任であり、本機能（問題単位の解答フィードバック）のスコープ外とする。
- `specs/027-map-quiz-hud` の契約C4（`BottomHudContent`）において、HUD経路では `kind: 'feedback'` バリアントを使用せず `kind: 'prompt'`（お題）のまま描画を維持する（4択単独セッションのカード経路では引き続き `FeedbackLine` を使用）。また `BOTTOM_BAND_FEEDBACK_PX`（56px）は廃止され、`bottomBandHeightPx` はフィードバック時も idle 高さ（通常 44px / Mode A 52px）を返すよう改定される。

## UI 設計案

### HUD経路（モードA・D、および地図混在セッション）
下部HUDの帯高さは出題中（idle）の高さ（通常 44px / Mode A 52px）を完全固定維持。帯はお題を表示し続け、TopHud直下のフローティングカードに答えと補足情報が集約される：

```text
┌─────────────────────────────────────────────────────────────┐
│ TopHud [離脱]  [3/10]                                      │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ 🎉 正解！ お見事！  [3連続]                             │ │
│ │ 館山市（たてやまし）  [☆☆ 中級]  |  人口 約4.4万人     │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│                      [ 地図表示領域 ]                       │
│              正解ポリゴンが一瞬パッと光る (Pulse)           │
│           (パン・ズーム操作はスキップせず維持される)        │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│ BottomHud (44px / Mode A 52px 完全固定・お題据え置き)       │
│ 館山市                                  [タップ/Spaceで次へ] │
└─────────────────────────────────────────────────────────────┘
```

### カード経路（4択単独セッションのモードB・C）
問題カード下部のフィードバック行に人口が追加され、バウンス演出が入る：

```text
┌─────────────────────────────────────────────────────────────┐
│                     問題カード                              │
│  ☆ 入門                                                    │
│  館山市                                                     │
│                                                             │

│  千葉県  |  人口 約4.4万人                                  │
└─────────────────────────────────────────────────────────────┘
```

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全出題モード（A/B/C/D）および復習クイズにおいて、正解時に難易度および人口データが漏れなく表示される（データ存在時100%）。
- **SC-002**: 政令指定都市（大阪市等）が出題された際、合算対象となる全区の人口の合計値が正しく算出され、FR-002d の丸め規則に従った単一の表記（例: 大阪市「約275.4万人」）となること（区単体の人口や欠損区を含む誤った合算値が表示されないこと）。
- **SC-003**: 画面幅 375px の実機表示において、TopHud直下のフローティングカードが地図の中心視認性を妨げず、BottomHudの高さ（通常 44px / Mode A 52px）が解答前後で一切変動しない（0px変動）。
- **SC-004**: スキップ入力（指定領域タップ／キー）を行った際、保存完了後 50ms 以内に次問への描画遷移が開始される。地図のドラッグ操作ではスキップが発火しない。
- **SC-005**: 375px モバイル実機での正解演出（CSS紙吹雪44粒アニメーション・カード表示・地図描画）において、50ms 超のロングタスク（フレーム落ち）が発生しない。
- **SC-006**: 画面幅 375px において、同名最多県（池田町・4県）の出題ケースでもカードが 112px 以内に収まり、全県の内訳がスクロールバーを出さずに表示される。
