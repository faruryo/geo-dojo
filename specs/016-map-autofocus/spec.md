# Feature Specification: 地図タップモード（Mode A/D）不正解時の自動フォーカス (B006)

**Feature ID**: `016-map-autofocus`  
**Backlog Reference**: `B006`  
**Created**: 2026-08-07  
**Status**: Draft  

---

## 1. 概要 (Overview)

geo-dojo の地図タップ型クイズ（Mode D: 順引き市区町村タップ / Mode A: 逆引き都道府県タップ）において、ユーザーが回答を間違えた際、正解の位置が現在のカメラ表示領域（ビューポート）外にあったり非常に小さく見えるため、「正解がどこにあったのか」を即座に視認・把握できない課題がある。

本機能（B006）では、不正解発生時（またはタイムアウト時）に**正解位置（および誤って選択した位置）が自動的に画面中央・最適ズームで収まるよう地図をスムーズにフォーカス（パン・ズーム）させる機能**を提供する。これにより、誤り位置と正解位置の視覚的対比を容易にし、学習効果を大幅に向上させる。

---

## 2. ユーザーストーリーとユースケース (User Stories & Use Cases)

### User Story 1: Mode D（順引き市区町村タップ）での不正解フォーカス
- **As a** クイズプレイヤー
- **I want** Mode D で市区町村の位置を間違えた（またはタイムアウトした）際、正解の市区町村（および誤タップした場所）へ地図が自動で寄る
- **So that** 自分がどこを誤り、本来どこが正解だったのかを拡大表示で直感的に確認できる

### User Story 2: Mode A（逆引き都道府県タップ）での不正解フォーカス
- **As a** クイズプレイヤー
- **I want** Mode A で都道府県を間違えて選択・送信した際、正解の都道府県（および誤選択した都道府県）へ日本地図が自動でズーム・移動する
- **So that** 正解の都道府県の位置関係を一目で復習できる

### User Story 3: 次のクイズへのスムーズなリセット
- **As a** クイズプレイヤー
- **I want** 次の問題に進んだとき、地図の拡大表示が元（Mode D: 都道府県全体フィット / Mode A: 全国俯瞰）にリセットされる
- **So that** 新しい問題にフラットな視点で取り組める

---

## 3. 機能要件 (Functional Requirements)

### FR-01: Mode D 不正解時の自動 Bounds フィット (Google Maps)
- **FR-01.1**: Mode D において `feedback === 'incorrect'` またはタイムアウト発生時、正解の市区町村の LatLngBounds を算出する。
- **FR-01.2**: 誤タップが存在する場合、誤タップの LatLngBounds と正解の LatLngBounds を合成した Bounding Box を算出する。
- **FR-01.3**: 算出された Bounding Box に対し、`google.maps.Map.fitBounds` を呼び出してスムーズにフォーカス・ズームさせる。
- **FR-01.4**: 極端な超拡大（小さな町単体で周辺地理が消えるケース）を防ぐため、`maxZoom` や `padding`（上右下左: 32px〜48px）の適切な下限・上限を適用する。

### FR-02: Mode A 不正解時の自動ズーム・パン (JapanMap / Simple Maps)
- **FR-02.1**: Mode A において回答送信後に不正解判定となった場合、正解の都道府県（`correctPrefectures`）および誤選択された都道府県（`selectedPrefectures`）の地理 coordinates 領域を特定する。
- **FR-02.2**: 該当領域がコンテナ画面中央に収まるよう `JapanMap` の `scale`（1〜8）および `translate` (`{x, y}`) を自動計算する。
- **FR-02.3**: `JapanMap` の SVG コンテナに CSS トランジション（`transition: transform 500ms ease-out`）を適用し、なめらかにフォーカス移動させる。
- **FR-02.4**: 正解が複数ある問題（例: 伊達市 → 北海道 & 福島県）では、すべての対象都道府県を含んだ Bounding Box を計算してフィットさせる。

### FR-03: 正解時・リセット時の挙動制御
- **FR-03.1**: 正解時（`feedback === 'correct'`）はカメラ移動を行わず、現在の表示状態またはハイライト強調のみを維持する（過度な画面揺れを防ぐため）。
- **FR-03.2**: `qIdx` が進んで新しい問題が開始される（`feedback === 'idle'`）際、カメラ表示位置を初期位置へリセットする。
  - Mode D: 対象都道府県の全市区町村 Bounds に `fitBounds`
  - Mode A: `scale: 1, translate: {x: 0, y: 0}`

---

## 4. 非機能要件 (Non-Functional Requirements)

- **UX / アニメーション**:
  - フォーカス移動のアニメーション完了時間は **500ms** を標準とする。
  - フィードバック表示時間（1500ms）のうち、最初の 500ms で移動完了し、残りの 1000ms でユーザーが落ち着いて視認できる構成とする。
- **モバイル対応**:
  - 375px 基準のモバイル端末で要素がヘッダー・フッターに隠れないよう安全な Padding を確保する。
- **性能**:
  - Bounds 計算処理は GeoJSON の静的座標から即座（< 10ms）に行い、レンダリング遅延を生じさせない。

## 5. エッジケースと境界条件 (Edge Cases)

| ケース | 状況 | 期待動作 |
|---|---|---|
| **離島・飛地を持つ市区町村** | 離島（例: 八丈町、高岡市飛地）を含む市区町村が正解 | 離島を含む全ポリゴンの包含 Bounds を計算し、切れずに収める |
| **遠隔地の複数正解 (Mode A)** | 北海道と鹿児島県など、極端に離れた複数県が正解 | Bounding Box が全国規模になるため `scale: 1`（全国表示）のままハイライト |
| **タイムアウト (Mode D)** | 誤タップせず時間切れ | 正解市区町村の Bounds のみにフォーカスする |
| **通信・地図読み込み失敗** | `onLoadError` 発生により Mode C (選択肢) へフォールバック | 自動フォーカスは起動せず Mode C の選択肢フィードバックに従う |
