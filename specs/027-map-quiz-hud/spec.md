# Feature Specification: 地図クイズのフルスクリーン HUD（GeoGuessr風）

**Feature Branch**: `faruryo/feat-ui-hud-ui-geoguessr`

**Created**: 2026-09-04

**Updated**: 2026-09-05（Claude Design での試作を反映。お題の導入表示、透過の不採用、帰属表示の配置、色とアクセシビリティを確定）

**Status**: Draft

**Input**: User description: "Issue #82 / B022。地図を操作するクイズで地図を画面いっぱいにし、問題・進捗・操作を端の小さなオーバーレイ（HUD）にする。中央には置かない。プレイ中はアプリのヘッダーとボトムナビを隠す。"

**Related**: GitHub Issue [#82](https://github.com/faruryo/geo-dojo/issues/82)、`specs/backlog.md` B022、B026（全国地図の縦画面最適化・本 spec の後続）

## 前提: 画面ごとに「フルスクリーン化」の効果が異なる

本機能は3つの出題画面を対象にするが、地図の描画方式が2系統あり、フルスクリーン化の効果が異なる。

| 画面 | 地図 | 縦長ビューポートでの挙動 |
|---|---|---|
| 場所当て（D） | Google Maps | 表示領域を与えた分だけ地図が広がる |
| 県当て（A）・都道府県クイズ | 全国 SVG 地図 | 縦横比が固定されており、**縦に広げても地図は大きくならず、上下に空白が増える** |

そのため本 spec では、**HUD の見た目と操作は3画面で統一**しつつ、地図そのものの拡大は場所当て（D）でのみ達成する。全国地図を縦画面いっぱいに使えるようにする作業（投影・フレーミングの作り直し）は本 spec の範囲外とし、後続の B026 で扱う。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 地図を画面いっぱいに使って解く (Priority: P1)

学習者は市区町村クイズの県当て（A）・場所当て（D）、または都道府県クイズを開始すると、アプリの上部ヘッダーと下部ナビが消え、画面は上端・下端の細い帯と、その間の地図だけになる。帯の間の領域は地図のためだけに使われ、ズーム・パン・タップを妨げるものが載らない。

**Why this priority**: 現行の縦積みでは地図が狭く、この機能の主目的（没入と操作性）そのものだから。

**Independent Test**: 対象クイズを開始し、上端・下端の帯以外に地図以外の常時表示がなく、ヘッダーとボトムナビが見えないこと。

**Acceptance Scenarios**:

1. **Given** ログイン済み学習者, **When** 市区町村クイズ A または D、あるいは都道府県クイズの出題画面に入る, **Then** 画面はビューポート全体を使い、アプリ共通のヘッダーとボトムナビは表示されない。
2. **Given** 出題中, **When** 画面を見る, **Then** 地図以外の常時表示は上端と下端の帯に収まり、その間には何も載っていない。
3. **Given** 出題中（幅 375px のモバイル想定）, **When** 帯の間の領域をドラッグ・ピンチする, **Then** 地図が操作でき、帯の上のボタンやお題では地図が動かない。
4. **Given** 場所当て（D）の出題中, **When** 現行レイアウトと比べる, **Then** 地図の描画面積が明確に広い（SC-007）。

---

### User Story 2 - お題は最初だけ大きく、あとは端で小さく (Priority: P1)

学習者は出題の瞬間、画面中央に大きく出たお題を読む。1秒ほどで、それは下端へ縮みながら移動し、
以後は 1 行の小さな表示として残る。読み損ねたら下端をタップすれば、また中央に大きく出る。
上端の帯では中断・進捗・（該当時）残り時間または経過タイムを見る。県当て（A）では下端に
解答確定もある。

**Why this priority**: お題を読む必要があるのは出題直後だけで、それ以降は思い出せる程度の
大きさで足りる。これにより定常状態の占有面積を最小にでき、地図を最下端近くまで使える。
「読ませる」責任を導入表示に移すことで、定常表示を小さくしても可読性を落とさずに済む。

**Independent Test**: 出題すると中央に大きくお題が出て、1秒ほどで下端の小さな表示に変わること。
下端をタップすると再び中央に大きく出ること。定常状態で上下の帯の合計が画面高の 15% 以下に
収まっていること。

**Acceptance Scenarios**:

1. **Given** 新しい問題が出た, **When** 画面を見る, **Then** お題が画面中央に 32〜36px で表示される。
2. **Given** 導入表示が出ている, **When** 1秒ほど待つ, **Then** お題は下端へ縮小移動し、1行 16px の
   定常表示になる。帯の高さは 44px（県当て A は 52px）。
3. **Given** 定常状態, **When** 下端のお題をタップする, **Then** お題が再び中央に大きく表示される。
   何度でも行える。
4. **Given** 場所当て（D）, **When** 導入表示が出ている間, **Then** 15秒の持ち時間はまだ減り始めて
   いない。導入が終わってから減り始める。一方、解答時間（SRS 用）と都道府県タイムアタックの
   経過タイムは、現行どおり問題の切り替わり時点から計測されている。
5. **Given** `prefers-reduced-motion: reduce` が有効, **When** 新しい問題が出た, **Then** 移動
   アニメーションは起こらず、最初から下端にあり、2.5 秒だけ大きく表示されてから通常サイズになる。
6. **Given** 解答して下端がフィードバック表示に変わる, **When** よみがなを含む最長の文言が出る,
   **Then** 折り返しても文字が帯の中に収まり、正解・不正解・文言の長短で高さが変わらない。
7. **Given** 出題中, **When** 上端を見る, **Then** 中断（離脱）、進捗、そのモードに時間表示があれば
   残り時間または経過タイム、効果音のオンオフが並ぶ。

---

### User Story 3 - 中断・完了後は通常の枠に戻る (Priority: P2)

学習者が中断する、または全問を終えると、フルスクリーン HUD を抜け、結果や設定など既存の画面構成（ヘッダーやナビがある通常レイアウト）に戻る。中断は誤操作で起きない。

**Why this priority**: 没入はプレイ中だけ。結果の振り返りと他画面への移動は既存の枠のほうが分かりやすい。プレイ中は出口が中断の1つだけになるため、誤爆すると復帰できない。

**Independent Test**: 出題中に中断、および全問終了のそれぞれで、フルスクリーンが解け、ナビまたは結果画面に戻れること。中断は1タップでは離脱しないこと。

**Acceptance Scenarios**:

1. **Given** 出題中, **When** 上端の中断を押す, **Then** 確認を求められ、承認した場合にのみ既存と同じ中断の扱いになり、通常の画面枠に戻る。
2. **Given** 中断の確認が出ている, **When** 取り消す, **Then** セッションは中断されず出題に戻る。
3. **Given** 最終問まで解答した, **When** 結果が出る, **Then** 結果表示はフルスクリーン HUD ではなく、既存の結果画面の流れに乗る。
4. **Given** クイズ開始前の設定画面, **When** 範囲や問数を選ぶ, **Then** レイアウトは現行のまま（フルスクリーン HUD にしない）。

---

### User Story 4 - 復習セッションでも画面構成が変わらない (Priority: P2)

復習セッションは1回の中に県当て（A）・都道府県4択（B）・市区町村4択（C）・場所当て（D）が混在する。学習者から見て、セッションの途中で画面の枠組みが切り替わることはない。

**Why this priority**: 混在は既存仕様であり、問題ごとに枠を切り替えるとボトムナビが点滅して最も体験が悪くなる。

**Independent Test**: A と B/C と D を含む復習セッションを最初から最後まで通し、ヘッダー／ボトムナビの表示状態が一度も変わらないこと。

**Acceptance Scenarios**:

1. **Given** 地図問題（A または D）を1問以上含む復習セッション, **When** セッションを開始する, **Then** セッション全体がフルスクリーン枠になり、4択の問題でも枠は維持される。
2. **Given** そのセッションで4択（B/C）の問題が出た, **When** 画面を見る, **Then** 選択肢は下端 HUD の領域に表示され、上端 HUD はそのまま使える。
3. **Given** 地図問題を1問も含まない復習セッション（4択のみ）, **When** セッションを開始する, **Then** 現行の通常レイアウトのままとする。

---

### Edge Cases

- お題が長い自治体名でも下端の帯からはみ出さない（折り返し・縮小で固定高さに収める）。
- ノッチやホームインジケータのある端末では、上端・下端の HUD がシステム領域と重なって押せなくならない。
- 場所当て（D）の地図読み込みに失敗し4択へフォールバックした場合も、セッションの枠組みは維持する（US4 と同じ扱い）。
- 残り時間があるモード（D）と経過タイムがあるモード（都道府県タイムアタック）は別物として上端に出す。どちらも無いモードでは枠を空けない。
- 不正解後の自動フォーカス（016）は、上下の HUD に隠れない領域に正解が収まるように寄る。
- 画面を横向きにした場合は対象外（縦向き前提）。

## Requirements *(mandatory)*

### レイアウトと適用範囲

- **FR-001**: 市区町村クイズの県当て（A）・場所当て（D）、および都道府県クイズの**出題中**は、ビューポート全体を使い、地図以外の常時表示を上端・下端の帯に限定しなければならない。
- **FR-002**: 上記の出題中は、アプリ共通のヘッダー（各ページ内の戻るリンク・タイトルを含む）とボトムナビゲーションを表示してはならない。
- **FR-003**: 上端・下端の帯の間には、地図以外の常時表示を置いてはならない。中断の確認など一時的なダイアログはこの限りではない。
- **FR-004**: **レイアウトの切替単位はセッションとする。** 1回のセッションに地図問題（A または D）が1問でも含まれる場合、セッション全体をフルスクリーン枠とし、同じセッション内の4択問題でも枠を維持する。地図問題を含まないセッションは対象外とする。
- **FR-005**: 場所当て（D）で地図の読み込みに失敗し4択へフォールバックした場合も、セッションの枠は維持しなければならない。
- **FR-006**: 市区町村クイズの県当て練習（B）・市当て練習（C）のみで構成されるセッション、モード一覧、各クイズの開始前設定、結果画面は、本機能のレイアウト変更対象外とする。
- **FR-007**: 中断および全問終了後はフルスクリーン枠を終了し、既存の結果・離脱後画面へ遷移しなければならない。
- **FR-008**: 本機能は縦向き（portrait）を前提とする。横向きでの最適化は行わない。

### 上端 HUD

- **FR-010**: 上端 HUD は中断、進捗（問題番号／総数）、効果音のオンオフを提供しなければならない。
- **FR-011**: **残り時間があるモード**（場所当て D の制限時間）では、上端 HUD に残量が減っていくことが分かる表示を出さなければならない。
- **FR-012**: **経過時間を計るモード**（都道府県クイズのタイムアタック）では、上端 HUD に増えていく経過タイムを数値で出さなければならない。FR-011 とは別の表示とする。
- **FR-013**: どちらの時間表示も持たないモードでは、時間表示のための領域を確保してはならない。
- **FR-014**: 中断は誤操作で発動してはならない。タップ領域を 44×44px 以上確保し、確認を1段挟まなければならない。

### 下端 HUD とお題の提示

お題を読む必要があるのは出題直後の短い時間だけである。そこで、お題は**導入（中央・大）
→ 定常（下端・小）**の2段階で提示し、定常状態の占有面積を最小にする。

- **FR-020**: 出題直後、お題は**画面中央に大きく**（32〜36px）表示しなければならない。これは
  一時的な表示であり、FR-003 の「常時表示」には当たらない。
- **FR-021**: 導入表示は 0.8〜1.2 秒後に**下端へ縮小移動**し、定常状態となる。定常状態のお題は
  1行・16px、下端の帯の高さは 44px（県当て A は確定ボタンの 44px タップ領域を収めるため 52px）
  とする。なお、この長さを将来ユーザー設定で短縮できるようにする余地は残すが（例: 0.2 秒）、
  本 spec では固定値とし、設定項目は設けない。
- **FR-022**: **定常状態の下端 HUD をタップすると、お題が再び中央に大きく表示されなければ
  ならない。** 難読地名と弱視の利用者にとって、1回きりの導入表示では読み取れない場合がある
  ため必須とする。再表示の操作対象であることが分かる手掛かり（拡大アイコン等）を伴うこと。
- **FR-023**: `prefers-reduced-motion: reduce` が有効なときは**移動アニメーションを行わない**。
  最初から下端に配置し、最初の 2.5 秒だけ帯と文字を大きく（帯 64px・文字 24px）してから
  通常サイズへ移すこと。
- **FR-024**: **場所当て（D）の制限時間のみ**、導入表示が完了してから計測を開始する。読んでいる
  間に持ち時間が減ってはならない。**次の2つは現行どおり、問題の切り替わり（`qIdx` の変化）時点から
  計測する**:
  - `answerTimeMs`（`components/quiz/use-quiz-state.ts` の `startTimeRef`）— SM-2 の quality 判定に
    使われ、10秒以内の正解が quality=5 として EF 加速と早期卒業（018）に効く
    （`lib/quiz/srs/quality.ts` の `FAST_ANSWER_THRESHOLD_MS`）。起点を遅らせると実質的な速答の窓が
    10.0 秒から 9 秒前後に縮み、定着間隔が変わる。FR-050 に反する。
  - 都道府県タイムアタックの経過タイム — localStorage の自己ベストと比較するため、起点を変えると
    過去の記録と比較できなくなる。
- **FR-025**: 解答直後の正否フィードバックは下端に出し、上下の帯の間を占有してはならない。
- **FR-026**: **正否フィードバックにはよみがなを含めなければならない。** 文言は既存の
  `feedback-labels.ts` に従い、次の3形がある。最長形は 375px 幅で折り返すため、**下端 HUD の
  フィードバック時の高さは最長形が折り返した状態を基準に決める**こと。
  1. 通常: `鶴岡市（つるおかし）`
  2. 同名が複数県にある: `府中市（ふちゅうし） （正解: 東京都・広島県）`
  3. 同名で読みが県ごとに違う: `大和町 （正解: 宮城県: たいわちょう / 神奈川県: やまとまち）`
- **FR-027**: 同一モード内で、**定常状態の下端 HUD の高さは問題をまたいで変化してはならない**。
  フィードバック時の高さは定常時と異なってよいが、フィードバックの3状態（正解・不正解・
  文言の長短）の間では一定でなければならない。
- **FR-028**: 県当て（A）で選択中の都道府県は、地図上の着色をもって示す。下端では件数のみを
  1行で表示し、選択ごとに高さが変わる表示をしてはならない。
- **FR-029**: 復習セッション中の4択問題（US4）では、選択肢を下端 HUD の領域に表示する。

### 地図とのすり合わせ

- **FR-030**: HUD の帯の外側では、地図のパン・ピンチ・タップが従来どおり使えなければならない。HUD 上の操作対象だけがタッチを受け取る。
- **FR-031**: 上端・下端の HUD はビューポート幅いっぱいの帯とする。四隅に浮かせるチップ状の配置はしない。
- **FR-032**: **地図の帰属表示は場所当て（D）にのみ置く。** Google Maps Platform の規約により
  ロゴと著作権表記は可視かつ非遮蔽でなければならず、Google Maps JS API はこれを地図コンテナ
  内の左下に描画し、位置を変更できない。したがって**下端 HUD は画面最下端に密着させ、地図
  コンテナの下端を帯の高さぶん縮める**こと。帯の下に地図が細く覗く隙間を作ってはならない。
  県当て（A）・都道府県クイズは国土数値情報の SVG 地図であり Google Maps を用いないため、
  **地図上に帰属表示を置かない**（出典は FR-041 の常設ページに集約する）。
- **FR-033**: 地図のズーム操作ボタンは、上端・下端の HUD と重ならない位置（画面の右側面・垂直方向の中央付近）に配置しなければならない。
- **FR-034**: **不正解後の自動フォーカス（016）の可視領域は、上端 HUD・下端 HUD・セーフエリアを除いた矩形とする。** 正解の対象がこの矩形の内側に収まるように寄せなければならない。
- **FR-035**: **HUD の背景は完全な不透明（`#111111`）とする。** 半透明・グラデーション・
  すりガラス（backdrop-filter）は用いない。これらは下地の地図の明度をそのまま拾うため、
  明るい Google Maps タイルの上ではコントラストが落ち、暗い SVG 地図の上との間で挙動が
  安定しない。不透明にすることで下地に依存せず、コントラストを数値で保証できる。
  「帯が大きい」問題は透過ではなく、FR-020〜021 のサイズ縮小で解決する。
- **FR-036**: 自前の塗りを持つ操作要素（確定ボタン等）は、その背景がコントラストを担保する
  ため、HUD の不透明域を要素の高さぶん広げる必要はない。

### 色とアクセシビリティ

- **FR-037**: **正否は文字色ではなく色付きアイコンで示す。** 文字は白（`#fafafa`、`#111111` 上で
  18.1:1）に統一し、正解は `#22c55e`、不正解は `#ef4444` のアイコン（塗り丸＋チェック／
  塗り丸＋×）を添える。アイコンは非テキストなので基準が 3:1 であり、どちらも満たす。
  文字色に色を用いると `#ef4444` が 5.02:1 となり、弱視向けの 7:1 に届かない。
  色だけに依存しない判別（形の違い）も同時に満たす。
- **FR-038**: 弱視の利用者を想定し、**通常サイズの文字は `#111111` 上で 7:1 以上**を確保する
  こと。22px 以上の太字は大きい文字として 4.5:1 でよい。地図の正解塗り `#4a7c59` は 3.88:1
  であり、**文字色には用いない**（塗りとしてのみ使う）。
- **FR-039**: HUD 内の最小文字サイズは 12px とする。

### 情報要素の行き先

- **FR-040**: 現行の出題画面にある情報要素は、次のとおり移設または廃止する。実装時に未定の要素を残してはならない。

| 現行の要素 | 移設先 | 備考 |
|---|---|---|
| 中断 | 上端 HUD | 確認を1段挟む（FR-014） |
| 進捗（N / M） | 上端 HUD | |
| 正解数（`N 正解`） | **廃止** | 出題中の判断に使わない。結果画面で振り返れる |
| 効果音トグル | 上端 HUD | |
| 残り時間バー・「残り N 秒」（D） | 上端 HUD | 細いバーとして（FR-011） |
| 経過タイム（都道府県 TA） | 上端 HUD | 数値表示（FR-012） |
| 難易度バッジ | **廃止** | 出題中に知っても行動が変わらない。HUD 縮小を優先 |
| お題（自治体名・都道府県名） | 下端 HUD | 最も可読性を優先する要素 |
| 「N か所あります」「あと N か所」（A） | 下端 HUD の**確定ボタンのラベルに統合** | お題側の重複表示は廃止 |
| 選択中の都道府県バッジ列（A） | 下端 HUD に**件数1行**として集約 | 個別の取り消しは地図の再タップで行う（FR-028） |
| 出題対象の都道府県名（D の副題） | 下端 HUD、お題と同じ行に小さく | どの県の地図かの手がかりとして残す |
| 正否フィードバック（かな・正解名） | 下端 HUD | お題と同じ枠を差し替え（FR-025, FR-026, FR-027） |
| 地図データ読み込み失敗メッセージ | 下端 HUD に1行 | |
| 出典表記（国土数値情報 / e-Stat） | **プレイ中は非表示**。常設の情報ページへ移設 | 移設は本 spec のスコープに含む（FR-041） |

- **FR-041**: 出典表記をプレイ中に非表示にするにあたり、アプリ内の常設ページから出典（国土数値情報・国勢調査 / e-Stat）が確認できる状態を維持しなければならない。

### 不変条件

- **FR-050**: 出題の正否判定、保存、SRS、効果音の意味は変えてはならない。変えるのは配置と占有面積である。
- **FR-052**: **実装のない情報を表示してはならない。** 特に場所当て（D）の判定は
  `isModeDTapCorrect(tappedCode, questionCode)` によるコードの一致判定のみであり、距離を
  測っていない。「N km ずれ」のような距離表示を出してはならない。
- **FR-051**: 375px 幅・ダーク表示を前提に、端の HUD が読め、主要操作が親指で届かなければならない。

### Key Entities

- **出題セッション（プレイ中）**: フルスクリーン枠＋上下 HUD が有効な期間。1回のセッション全体が単位であり、問題ごとに切り替わらない。開始前設定と結果表示は含まない。
- **上端 HUD**: 中断・進捗・時間（残りまたは経過）・音量。状態と離脱。高さ固定。背景は不透明。
- **導入表示**: 出題直後に画面中央へ大きく出るお題。0.8〜1.2 秒で下端へ縮小移動する一時的な表示。
  下端タップで再び現れる。タイマーはこの表示が終わってから動き出す。
- **下端 HUD**: 定常状態のお題（1行 16px）、A の確定と選択件数、正否フィードバック（よみがなを含む）、
  復習時の4択。背景は不透明 `#111111`。定常状態の高さは 44px（A は 52px）で固定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 出題中の定常状態で、上端 HUD と下端 HUD の合計高さが画面高の **15% 以下**である（375×812 で 122px 以下）。
- **SC-002**: 幅 375px で、お題の自治体名が 16px 以上で表示され、中断・確定などの操作対象が 44×44px 以上で、追加の画面スクロールなしに押せる。
- **SC-003**: 学習者は、フルスクリーン化の前後で同じ手順（タップで解答、A は確定あり）で1問を完了できる。手順の追加学習を要求しない。
- **SC-004**: 開始前設定、結果画面、および4択のみで構成されるセッションは、見た目・操作が現行から実質変わらない。
- **SC-005**: 出題中にボトムナビが見えず、中断（確認を経て）または完了のあと通常の画面枠に戻れる。
- **SC-006**: 上端 HUD と下端 HUD の矩形の外側であれば、画面上のどの点からでも地図のパン・ピンチが開始できる。
- **SC-007**: **場所当て（D）において、地図の描画面積が現行比 130% 以上になる。**（県当て A・都道府県クイズは全国 SVG 地図の縦横比が固定のため本 SC の対象外。B026 で扱う）
- **SC-008**: 問題が切り替わっても、定常状態の下端 HUD の高さが変化しない。正否フィードバック中も、
  文言の長短や正解・不正解の別によって高さが変化しない（最長形が折り返した状態が基準）。
- **SC-010**: 定常状態の下端 HUD をタップすると、お題が中央に大きく再表示される。何度でも行える。
- **SC-011**: `prefers-reduced-motion: reduce` を有効にすると、中央から下端への移動アニメーションが
  起こらない。
- **SC-012**: 場所当て（D）で、下端 HUD が画面最下端に密着し、その下に地図が覗く隙間がない。
  Google のロゴと著作権表記は帯の直上に可視で残っている。
- **SC-013**: HUD 内の通常サイズの文字が `#111111` 上で 7:1 以上、最小 12px 以上である。
- **SC-009**: A と B/C と D を含む復習セッションを通しで実施したとき、ヘッダー／ボトムナビの表示状態が一度も変化しない。

## Assumptions

- 対象は Issue #82 どおり市区町村 A/D と都道府県クイズの出題中。4択のみのセッションと設定画面は対象外。
- 結果画面は既存のカード型のままとする（結果まで地図フルスクリーンにはしない）。
- 正否の大きな中央モーダルは出さない。フィードバックは下端。中断の確認は一時的なダイアログとして許容する。
  出題直後のお題の導入表示（中央・大）も一時的な表示であり、この方針に反しない。
- 出題ロジック・DB・推薦は変更しない。
- デスクトップでも同じ上下帯の配置とする（別レイアウトは作らない）。横向きは対象外。
  なお 1440×900 での試作では、**厚い帯のまま幅いっぱいにすると中身が左端に取り残され、右に
  1200px 以上の空白が残る**ことが確認された。本 spec の帯は 44〜52px と薄いため、この破綻は
  起きない。デスクトップで帯を厚くする変更を加えてはならない。
- 暗黙の「戻る」は上端の中断に集約する（ボトムナビを消す代わり）。
- 県当て（A）・都道府県クイズでは、全国 SVG 地図の縦横比により地図の上下に余白が生じる。本 spec ではこの余白の位置に HUD を置く形になり、地図面積は増えない。地図を縦画面いっぱいに使うための投影・フレーミングの作り直しは B026 で行う。
  **027 と B026 は続けて実施する前提とする。** B026 を実施しない場合、県当て・都道府県では地図が
  広がらないままとなり、Issue #82 の動機（地図が狭い）が3画面のうち2つで満たされない。
- `setup / playing / result` は同一ルートのクライアント状態であるため、フルスクリーン枠への切替は既存ルート構成のまま行う。プレイ中だけ別ルートに分割する方式は採らない（設定から出題への状態受け渡しを作り直すコストが本機能に見合わないため）。
- 透過（半透明・グラデーション・すりガラス）は検討のうえ**不採用**とした。試作で計測した
  ところ、すりガラス（不透明度 66% + blur 18px）では下地の地図の明度を拾い、明るい Google Maps
  タイルの上でコントラストが 4.7〜5.2:1 まで落ちた。暗い SVG 地図の上との間で挙動が安定せず、
  弱視向けの 7:1 を数値で保証できない。「帯が大きい」問題は透過ではなくサイズで解決する。
- 導入表示（中央・大）のあいだ、地図はタップを受け付けてよいものとする。導入表示は地図の
  中央を一時的に覆うが、この時点ではまだ計測が始まっていないため、誤タップの損失はない。
