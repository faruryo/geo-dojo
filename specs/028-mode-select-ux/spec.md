# 機能仕様書: 市区町村クイズモード選択画面のUX改善（導線可視化・おすすめ省スペース化・サンプル誤認防止）

**フィーチャーブランチ**: `faruryo/feat-ui-ux`
**作成日**: 2026-09-13
**ステータス**: 設計完了・実装前
**インプット**: GitHub Issue [#87](https://github.com/faruryo/geo-dojo/issues/87) / Backlog B027

---

## 背景 / 問題

市区町村クイズのモード選択画面（`/quiz/municipality`）は、初めて訪れたユーザーが「設定へ進む」までにたどり着けない。
375×667 の実測で、CTA はファーストビューの **334〜376px 下**にある（モードにより変動）。

ファーストビューの下端は 667 − `BottomNav` 59px = **608px**（実測）。
高さは `app/globals.css` の `@layer base` にある `button, a, [role="button"] { min-height: 44px }` の影響を受ける。
`Button` の `size="default"` は `h-8`（32px）だが `min-height` が勝って 44px になり、戻るリンクの `<a>` も同じく 44px。

| 選択モード | CTA 上端 | fold からの距離 | 画面全体の高さ |
|---|---|---|---|
| A（県当て・地図） | 970 | 362px 下 | 1237 |
| B / C（4択・練習） | 942 | 334px 下 | 1209 |
| D（場所当て・地図） | 984 | 376px 下 | 1251 |

モードを切り替えると CTA が最大 42px 動く点も、押そうとした位置がずれる問題として同じ構造から出ている。

`min-h-[30rem]`（480px）はプレビューの下限として効いており、実コンテンツが 288px の B / C を 480px まで引き伸ばしている。
そのぶん B / C でも CTA が fold 外へ押し出され、**初見時の既定（`resolveInitialSelectedMode` の `fallbackMode: 'B'`）でも見えない**。

## ユーザーシナリオとテスト (必須)

### ユーザーストーリー 1 - スクロールせずにモードを選んで進める (優先度: P1)

初見ユーザーが 375×667 の端末でモード選択画面を開き、スクロールせずにモードを選び、そのまま設定画面へ進める。

**受入シナリオ**:
1. **Given** 375×667 でモード選択画面を開いたとき, **When** 画面をスクロールしない, **Then** モードカード4枚と CTA ボタンがすべて可視域（608px）内に収まっている。
2. **Given** モードカードをタップしたとき, **When** CTA ボタンを見る, **Then** 選択したカードがハイライトされた直下に CTA があり、視線移動なしで押せる。
3. **Given** CTA をタップしたとき, **When** 遷移先を確認する, **Then** `/quiz/municipality/<選択モードの小文字>` の設定画面が開く。
4. **Given** モードを切り替えたとき, **When** CTA の位置を見る, **Then** モードによって CTA の y 座標が動かない。

### ユーザーストーリー 2 - おすすめクイズを必要な時だけ開く (優先度: P1)

自分でモードを選びに来たユーザーの画面領域を、おすすめクイズが占有しない。必要なときはワンタップで開ける。

**受入シナリオ**:
1. **Given** モード選択画面を開いたとき, **When** 画面上部を見る, **Then** 「今日のおすすめクイズ」は見出し行のボタン1つに収まり、カードとしての縦領域を占有していない。
2. **Given** そのボタンをタップしたとき, **When** 画面を見る, **Then** 既存の `RecommendSheet` が下から開き、推薦内容（モード・難易度・問題数・理由）を確認して開始できる。
3. **Given** `/quiz/municipality?recommend=open` で画面を開いたとき, **When** 画面を見る, **Then** シートが開いた状態で表示される。
4. **Given** ホーム画面（`/`）を開いたとき, **When** 画面を見る, **Then** 従来どおり `RecommendHeroCard` が展開表示されている（この画面の変更はホームに波及しない）。

### ユーザーストーリー 3 - サンプルを本番と誤認しない (優先度: P2)

プレビューが「触れないプレイ画面イメージ」であることが一目で分かる。

**受入シナリオ**:
1. **Given** モード選択画面をスクロールしてプレビューに達したとき, **When** プレビューを見る, **Then** 「プレイ画面イメージ」のラベルと、本番UIと区別できる枠（破線）が付いている。
2. **Given** プレビュー内の選択肢や地図をタップしたとき, **When** 画面の変化を見る, **Then** 何も起こらず、かつ「押せない見た目」（減光・テキスト選択不可）であることが視覚的に伝わる。
4. **Given** CTA から Tab キーでフォーカスを進めたとき, **When** フォーカスの移動先を見る, **Then** プレビュー内（地図の都道府県を含む）には一切入らず、出題ルールの開閉へ進む。
3. **Given** プレビューと CTA の位置関係を見たとき, **Then** プレビューは CTA より下にあり、破線枠とラベルで本番の操作領域と分離されている。

## 機能要件 (必須)

- **FR-001**: モード選択画面の DOM 順を「見出し → モードカード → CTA → プレビュー → 出題ルール」に変更する。説明ブロック（プレビュー・出題ルール）は CTA より後に置く。
- **FR-002**: 375×667 において、モードカード4枚と CTA が可視域 608px 内に収まること。実測 CTA 272–316（fold まで 292px の余裕）。
- **FR-003**: CTA の文言を「このモードで遊ぶ」の固定文言にする。直上にモード名が表示されるため、ボタンにモード名を再掲しない。
- **FR-004**: 選択中モードの説明（`description`）は CTA の上に置かない。`longLabel` は選択中のモードカードに出ているため見出しとして再掲せず、`description` はそれが説明している対象であるプレビューの枠のキャプションに置く。CTA の上に可変長のテキストが無くなるので、モードを切り替えても CTA の y 座標は動かない。
- **FR-005**: `md` 以上では左カラム（モードカード → CTA）／右カラム（プレビュー → 出題ルール）の2カラムとし、CTA を左カラム内に置く。現行の「CTA だけ grid の外に全幅」を解消する。
- **FR-006**: この画面から `RecommendHeroCard` の使用をやめ、戻るリンクと同じ行の `ghost` ボタン「✨ おすすめ」から既存の `RecommendSheet` を開く。h1 の行に置くと 375px で見出しが2行に折り返すため、右が空いている戻るリンクの行に置く。シートの開閉状態は既存の `useRecommendSheet` を用い、`?recommend=open` のディープリンクと戻る操作での閉じる挙動を維持する。
- **FR-007**: `RecommendHeroCard` 自体および `components/dashboard/dashboard-client.tsx`（ホーム）の表示は変更しない。
- **FR-008**: `ModePreviewA`〜`D` の中身は変更せず、外側に1枚のラッパーを設けて次を与える: 「プレイ画面イメージ」ラベル、破線枠、地図が判別できる程度（不透明度 0.85 前後）の減光、および中身の非操作化。
- **FR-008a**: 非操作化はポインタだけでなく**キーボードにも効かせる**。中身に `inert` を付ける（`pointer-events-none` / `select-none` は併用するが、それだけでは不足）。
  `MiniJapanMap` が使う react-simple-maps の `Geography` は各 SVG パスに `tabIndex={0}` を固定で付け、`MiniJapanMap` 側は `outline: 'none'` を指定しているため、
  ポインタだけを止めるとフォーカス位置の見えないタブストップが 47 個できる。ラベルは枠の外に置き、読み上げ対象として残す。
- **FR-009**: プレビューを本番の操作領域と視覚的に分離する。分離は FR-008 のラッパー（破線枠と「プレイ画面イメージ」ラベル）が担い、その上に「以下は参考」のような区切り文は置かない。枠の直上で同じことを二度言うことになるため。
- **FR-010**: 375px 幅・ダークモード（`#111111`）で、操作対象は 44×44px 以上を維持する。本フィーチャーで新設するラベル（「プレイ画面イメージ」）は、サンプルだと気付かせるために読ませる要素なので `text-xs`（12px）以上にする。既存の `text-[11px]` / `text-[10px]` の補助テキストはこの PR では触らない。

## 非スコープ

- `ModePreviewA`〜`D` の内容・表現の作り替え（4択の正解色を含む）。誤認防止はラッパーで達成する。
- `MiniJapanMap`（h-72 / 288px）の縮小。CTA が上に移ることで fold 外になるため縮める必要がない。
- 設定画面（`app/(app)/quiz/municipality/[mode]/page.tsx`）の変更。
- 都道府県クイズ（`/quiz/prefecture`）およびクイズ選択画面（`/quiz`）の変更。

## 採用しなかった案

| 案 | 却下理由 |
|---|---|
| 画面下部フローティング CTA バー | 選択とアクションが離れたまま（構造上の原因が残る）。`bottom-nav`（`fixed bottom-0`, ~56px + safe-area）の上に浮かせる必要があり、375px の縦に帯が二段でき、プレビュー地図がさらに潰れる。 |
| モードカード直結（タップで即遷移） | B018 で入れた「前回選択モードを保持してハイライトする」仕組みと噛み合わない（ハイライトを見る間もなく遷移する）。誤タップが遷移になる。 |
| `RecommendHeroCard` に `compact` variant を追加 | 共通コンポーネントが2つのレイアウトを抱える。ホームでは「理由を読ませてから押させるカード」、この画面では「存在を知らせてシートを開くボタン」で責務が違う。 |
| おすすめカードを `<details>` で折りたたむ | 折りたたみ行そのものが ~44px を占める。開くとモードカード以下を 140px 押し下げ、この画面での主目的（モード選択）を再び妨げる。 |

## 成功基準 (必須)

- **SC-001**: 375×667 でモード選択画面を開き、スクロールせずにモードを選んで設定画面へ進める（実測 CTA 下端 316 < fold 608）。
- **SC-002**: モードを A/B/C/D と切り替えても CTA の y 座標が変わらない（実測 4モードとも 272–316 で不動。現行は 942〜984 で 42px 動く）。
- **SC-003**: おすすめクイズが縦領域を占有しない（戻るリンク行のボタンのみで、高さ増加 0px）。
- **SC-004**: プレビュー内の要素はタップでもキーボード（Tab）でも到達できず、サンプルであることがラベルと枠で示されている。
- **SC-005**: ホーム画面のおすすめ表示と `?recommend=open` のディープリンクが従来どおり動く。
- **SC-006**: `pnpm type-check` / `pnpm lint` / `pnpm test` がすべてパスし、CTA の埋もれに対する回帰テストが1本追加されている。
