# Feature Specification: 詳細分析の期間初期値と長期の正答率推移

**Feature Branch**: `031-analytics-all-period`

**Created**: 2026-10-10

**Status**: Draft

**Input**: User description: "詳細分析画面の期間フィルター初期選択を「7日」から「全期間」に変更し、データが少ない週でもこれまでの学習推移を見やすくする。長期利用（1年超）では正答率推移の点が密集しないよう、集計のまとまりを週から月へ切り替える。手動で選んだ期間は、その学習者のこの端末に覚えて次回も使う。期間の選択肢そのもの、正答率・難易度の計算は変えない。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 開いただけでこれまでの推移を見る (Priority: P1)

週に1〜2回しかプレイしない学習者は、詳細分析を開いたとき「7日」ではなく「全期間」が選ばれている。正答率推移と苦手ランキングは、直近7日にデータが少なくても、これまでの回答に基づいて表示される。7日分だけを見たいときは、自分で「7日」に切り替える。

**Why this priority**: いまの初期値が学習の動機（蓄積を見たい）とずれていて、毎回切り替えないとグラフも苦手も空になりやすい。ここが直らないと長期集約も記憶も意味が薄い。

**Independent Test**: 直近7日は1日分しかなく、それより前に回答がある学習者で詳細分析を開く。期間が「全期間」で、7日より広い推移と苦手が出ることを確認する。

**Acceptance Scenarios**:

1. **Given** 保存された期間の選択がない学習者, **When** 詳細分析を開く, **Then** 期間は「全期間」が選ばれ、正答率推移・全国制覇推移・苦手ランキングは全期間の回答を対象にする。
2. **Given** 直近7日の回答が1日以下で、それ以前に回答がある学習者, **When** 詳細分析を初めて開く, **Then** 「データが少ないため推移は2日目以降に表示されます」だけで終わらず、7日より前を含む推移が見える。
3. **Given** 詳細分析を開いた直後, **When** 画面が出る, **Then** 直近7日のグラフが一瞬出てから全期間に差し替わらない。
4. **Given** まだ1問も回答していない学習者, **When** 詳細分析を開く, **Then** 期間の初期値が全期間でも、既存の空状態の案内のままエラーにならない。

---

### User Story 2 - 長く使っても正答率の線が読める (Priority: P2)

1年以上続けた学習者は、全期間の正答率推移が週の点のまま密集しない。履歴が1年以内なら週のまとまり、1年を超えたら月のまとまりになる。横軸の文字は携帯の幅でも重ならず、点を押すと省略していない期間が読める。

**Why this priority**: 初期値を全期間にすると、数年後は週の点が百を超え、375px幅では線もタップも読めなくなる。初期値変更の副作用を同じ画面で防ぐ。

**Independent Test**: 最初の回答から最後の回答までが1年以内の履歴と、1年を超える履歴をそれぞれ全期間で表示し、まとまりと横軸の読みやすさを確認する。

**Acceptance Scenarios**:

1. **Given** 全期間の対象回答が、最初から最後まで52週（364日）以内, **When** 正答率推移を見る, **Then** 点は月曜始まりの週ごとにまとまり、点の数は週の数を超えない。
2. **Given** 全期間の対象回答が、最初から最後まで364日を超える, **When** 正答率推移を見る, **Then** 点は月ごとにまとまり、5年でも週次のような百数十点にはならない。
3. **Given** 全期間を表示している, **When** 幅375pxで横軸を見る, **Then** 隣り合うラベルは重ならない。週は週開始の月日（例: 10/6）、月は同じ年内なら「10月」、複数年なら年と月（例: 26/10）と読める。点が収まらないときはラベルを間引いてよい。
4. **Given** 全期間の点を押したとき, **When** 説明を見る, **Then** 週は「その週の開始日」、月は「年と月」が省略されずに読める。
5. **Given** 期間が「7日」または「30日」, **When** 正答率推移を見る, **Then** 点は日ごとのままである。

---

### User Story 3 - 選んだ期間を次回も使う (Priority: P3)

学習者は「30日」などに切り替えたあと、同じ端末で次に詳細分析を開いてもその期間のまま見られる。別の学習者に切り替わったときは、前の人の選択を使わない。

**Why this priority**: 初期値を全期間にしても、直近だけ見たい人は毎回戻したくない。ただし未保存時の全期間表示が先に成り立っていれば、記憶がなくても価値は出る。

**Independent Test**: 「30日」を選んで詳細分析を開き直し、同じ学習者では「30日」、別の学習者ではその人の保存か、なければ「全期間」になることを確認する。

**Acceptance Scenarios**:

1. **Given** 学習者が期間を「30日」または「7日」に変えた, **When** 同じ端末・同じ学習者で詳細分析を再び開く, **Then** 最後に選んだ期間が選ばれ、推移と苦手ランキングもその期間に合う。
2. **Given** 学習者Aが「7日」を選んで保存されている, **When** 同じ端末で学習者Bが詳細分析を開く, **Then** Aの「7日」は使われず、Bの保存がなければ「全期間」になる。
3. **Given** 保存された期間が空、または「7日」「30日」「全期間」のどれでもない, **When** 詳細分析を開く, **Then** 「全期間」に戻る。
4. **Given** 期間を覚えた学習者, **When** 地方やモードを変えて開き直す, **Then** 地方とモードはこれまでどおり初期値（全国・全て）に戻り、覚えているのは期間だけである。

---

### Edge Cases

- 回答が1件だけ、または同じ週だけのとき: 全期間は週のまとまりで1点になり、点は表示される。空状態の「2日目以降」にはしない。
- 最初の回答と最後の回答の間隔がちょうど364日: 週のまとまりのまま。364日を1日でも超えたら月のまとまり。
- 回答と回答のあいだに空の週や月がある: 回答がないまとまりの点は足さない。
- 地方やモードで絞り込んだ結果、見える回答の最初から最後までが364日以内: アカウント全体がそれより長くても、その表示は週のまとまり。超えていれば月のまとまり。
- 期間を「7日」「30日」にしているあいだは、履歴が何年あっても日ごとのまま。
- 全国制覇推移は、選ばれた期間の対象日に従うが、点のまとめ方（日ごと）は変えない。
- 同名で複数県にある市の1問、難易度ごとの正答率、東京23区を県当て系の母数から外すルールは、まとまりが週でも月でも維持する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 詳細分析は、その学習者の保存された期間がなければ、期間「全期間」を選んだ状態で開かなければならない。
- **FR-002**: 開いた直後の正答率推移、全国制覇推移、苦手ランキングは、選ばれている期間の回答だけを対象にしなければならない。初期表示では全期間である。
- **FR-003**: 開いた直後に、別の期間のグラフを見せてから全期間へ差し替えてはならない。
- **FR-004**: 期間の選択肢は「7日」「30日」「全期間」の3つのままにしなければならない。
- **FR-005**: 「7日」と「30日」の正答率推移は、日ごとの点のままにしなければならない。
- **FR-006**: 「全期間」の正答率推移は、対象回答の最初の日から最後の日までが364日以内なら、月曜始まりの週ごとにまとめなければならない。
- **FR-007**: 「全期間」の正答率推移は、その間隔が364日を超えるなら、月ごとにまとめなければならない。回答がある月だけを点にし、5年分でも週次の百数十点には戻さない（端の月を含めると60前後）。
- **FR-008**: 「全期間」の横軸は、幅375pxで隣り合うラベルが重ならない短さにしなければならない。週は週開始の月日、月は年内なら月、複数年なら年と月が区別できること。点が入りきらないときはラベルを間引いてよい。
- **FR-009**: 「全期間」の点を押した説明では、週は週の開始日、月は年と月を省略せず読めなければならない。
- **FR-010**: 学習者が選んだ期間は、その学習者とその端末の組で覚え、次に詳細分析を開いたとき復元しなければならない。
- **FR-011**: 別の学習者の期間選択を表示に使ってはならない。保存が読めない、または不正な値のときは「全期間」にしなければならない。
- **FR-012**: 地方とモードの選択は覚えず、詳細分析を開き直したときの初期値は全国・全てのままにしなければならない。
- **FR-013**: 正答率の計算、難易度のまとめ方、Mode A の1問1件への正規化、県当て系から東京23区を外すルールを、この変更で変えてはならない。
- **FR-014**: 全国制覇推移の点は日ごとのままにしなければならない。変わるのは、どの期間を初期選択し、どの期間を覚えるかだけである。

### Key Entities

- **期間選択**: 詳細分析で選ぶ「7日」「30日」「全期間」。初期値は「全期間」。学習者と端末の組で1つ覚える。
- **正答率の点**: ある期間のまとまり（日、週、または月）における難易度別の正答率。週は月曜始まり。月は暦月。回答がないまとまりは点にしない。
- **対象期間の長さ**: いま表示している絞り込み（期間・地方・モード）に含まれる最初の回答日から最後の回答日までの日数。全期間の週か月の切り替えに使う。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 期間を保存していない学習者の100%が、詳細分析を開いた時点で「全期間」を見て、追加の操作なしに7日より前の回答を含む推移と苦手を確認できる。
- **SC-002**: 直近7日が1日以下でも、それより前に回答がある学習者は、初回表示で空の推移メッセージだけにならない。
- **SC-003**: 履歴が5年あっても、全期間の正答率推移は月ごとの点になり、幅375pxで横軸ラベルが重ならない。
- **SC-004**: 履歴が52週以内の全期間表示では、点は週の数以下であり、「7日」「30日」に切り替えると日ごとの点に戻る。
- **SC-005**: 期間を変えた学習者は、同じ端末で再び開いたとき、その期間が復元される。同じ端末の別の学習者には、その選択が現れない。
- **SC-006**: 既存の期間3択、空状態、正答率と制覇の数え方を知っている学習者が、期間の初期値と全期間の点の粗さ以外の違いを見つけない。

## Assumptions

- 「1年以内」は、表示中の回答の最初の日から最後の日までが364日以内（52週×7日）を指す。ちょうど364日は週、364日を超えたら月。今日までの経過年数ではなく、見えている回答の端と端で判定する。
- 週の開始は月曜。月は暦月（1日始まり）。
- 横軸の短い表記は、週が `10/6`（月/日）、月が同じ年なら `10月`、複数年なら `26/10`（年下2桁/月）とする。点を押した説明はそれぞれ `2026/10/6の週`、`2026年10月` とする。
- 覚える場所はこの端末の中だけで、ほかの端末へは引き継がない。
- 全国制覇推移を週や月にまとめることは今回しない。長期の制覇グラフの密度は別件とする。
- ダッシュボード（ホーム）に同じ期間フィルターはなく、この変更の対象は詳細分析である。
