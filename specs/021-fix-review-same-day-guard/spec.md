# Feature Specification: 復習セッションの同日ガード条件適正化と無限ループ解消

**Feature Branch**: `021-fix-review-same-day-guard`  
**Created**: 2026-08-15  
**Status**: Draft  
**Input**: User description: "復習をクリアした後の画面がバグってる。続けて復習するのボタンの件数が復習する前と変わらない。つまり全く同じ問題を復習できてしまう。それをクリアした後の画面でも同じ件数が出てしまう。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 復習期日を迎えているアイテムの正解で期日が正常に前進し、残り件数が減算される (Priority: P1)

ユーザーが復習セッションで期日（`dueDate`）を迎えている問題を解いて正解した際、同日に過去の回答履歴が存在するアイテムであっても、復習正解として正しく SM-2 間隔反復の期日が未来（翌日以降）に延長される。セッション完了後の結果画面において、期日超過の残り件数（`dueCount`）が消化した問題数に応じて正しく減少し、表示される。

**Why this priority**: 復習機能の根幹であり、解いた問題が消化されないと学習の進捗が一切記録されず復習機能が破綻するため。

**Independent Test**: 期日を迎えている復習アイテムを持つ状態で復習クイズをプレイし正解する。結果画面の「続けて復習する（残り N 件）」の件数が、正解した問題数分減少していることを確認する。

**Acceptance Scenarios**:

1. **Given** 復習期日を迎えている（`dueDate < JST翌日開始`）アイテムが 20 件ある、**When** 復習クイズで 20 件すべてに正解してセッションを完了する、**Then** 結果画面の残り件数は 0 件となり、「続けて復習する」ボタンは非表示（または完了状態）になる。
2. **Given** 復習期日を迎えているアイテムが 25 件ある、**When** 1バッチ目（20件）をすべて正解して完了する、**Then** 結果画面のボタンに「続けて復習する（残り5件）」と表示される。
3. **Given** 今日作成・回答されたアイテムであっても期日を迎えている状態（`dueDate` が過去/今日）にある、**When** 復習で正解する、**Then** 同日ガードでスキップされず、期日が翌日以降へ前進する。

---

### User Story 2 - 「続けて復習する」で消化済み問題が再出題されず、残りの問題が出題される (Priority: P1)

ユーザーが1バッチ目の復習を完了し、「続けて復習する」を選択した際、1バッチ目で消化済みの問題は除外され、残りの未消化な期日超過問題のみが出題される。

**Why this priority**: 全く同じ問題が連続で出題される無限ループを解消し、未消化の復習をスムーズに進められるようにするため。

**Independent Test**: 25件の期日超過アイテムがある状態で1バッチ目（20件）を完了し、「続けて復習する」を押下。次バッチで1バッチ目と重複しない残り5件が出題されることを確認する。

**Acceptance Scenarios**:

1. **Given** 25件の期日超過アイテムがある状態で1バッチ目（20件）を終えて「続けて復習する」を押す、**When** 2バッチ目が開始される、**Then** 1バッチ目で正解した20件は出題されず、残りの5件が出題される。
2. **Given** 2バッチ目の5件を解いて完了する、**When** 結果画面が表示される、**Then** 残り件数は0件となり、「今日の復習はありません」または完了状態が表示される。

---

### User Story 3 - 誤答履歴に基づく早期卒業判定の正常化 (Priority: P2)

過去に誤答履歴（`isCorrect = false`）があるアイテムは通常コース（一定以上の反復と間隔）で慎重に定着させ、過去に一度も誤答していないアイテムのみを早期卒業（`repetition >= 2` で卒業）させる。

**Why this priority**: 誤答履歴判定の論理反転により、苦手な問題が誤って2回の正解で早期卒業してしまう不整合を防ぐため。

**Independent Test**: 誤答履歴のあるアイテムとないアイテムで2回目の正解を行った際、誤答履歴があるアイテムは `reviewing` のまま間隔が伸び、誤答履歴がないアイテムのみが `graduated` になることを確認する。

**Acceptance Scenarios**:

1. **Given** 過去に誤答履歴があるアイテム、**When** 2回目の正解（`rep=2`）を達成する、**Then** 早期卒業せず `status = 'reviewing'` のまま通常間隔（6日など）で進行する。
2. **Given** 過去に誤答履歴が一度もないアイテム、**When** 2回目の正解（`rep=2`）を達成する、**Then** 早期卒業が適用され `status = 'graduated'` となる。

---

### Edge Cases

- **同日中の2回目以降の通常正解**: すでに今日正解して期日が未来（`dueDate >= JST翌日開始`）に前進済みのアイテムが、通常クイズで同日中に再度出題・正解された場合は、FR-005a に従い前進をスキップ（1日1回前進の原則を維持）する。
- **不正解時のリセット**: 不正解時は同日ガードの対象外であり、今日すでに回答済みであっても常に期日・反復回数のリセット（翌日 due / rep 0）が適用される。
- **期日境界（JST日付変更時）**: JST 0:00 を跨いだ瞬間に正しく翌日の due 判定が適用される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、復習アイテムの正解時における同日前進スキップ（同日ガード）の判定において、アイテムの最終回答日（`lastReviewedAt`）が同日であっても、**現在の期日（`dueDate`）が未到来（明日以降）でない限り前進をスキップしてはならない**（期日到来中のアイテムは同日回答履歴があっても正解で前進させる）。
- **FR-002**: システムは、期日が明日以降（`dueDate >= JST翌日開始`）かつ最終回答日が今日（JST同日）のアイテムに正解した場合に限り、同日中の重複前進をスキップしなければならない。
- **FR-003**: システムは、復習セッション完了後に「続けて復習する」ボタンを表示する際、最新の期日超過件数（`dueCount`）を正確に反映し、0件の場合はボタンを非表示（または完了状態）にしなければならない。
- **FR-004**: システムは、クイズ結果保存時の誤答履歴判定において、過去に不正解レコードが存在する場合に `everWrong = true`、存在しない場合に `everWrong = false` と正しく判定しなければならない。

### Key Entities *(include if feature involves data)*

- **`srs_records`**: 間隔反復の学習状態テーブル。`dueDate`（復習期日）、`lastReviewedAt`（最終復習日時）、`status`（`reviewing` / `graduated`）、`interval`、`repetition` を保持。
- **`municipality_quiz_results`**: クイズ回答履歴テーブル。`isCorrect`（正誤）、`answeredAt`（回答日時）を保持し、`everWrong` の判定元となる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 復習セッションで正解した期日超過問題は 100% 確実に期日が翌日以降へ前進し、直後の結果画面で残り件数が正解数分減少する。
- **SC-002**: 「続けて復習する」を実行した際、直前に正解した問題が再出題される重複率が 0% となる。
- **SC-003**: 既存の SM-2 間隔反復テストおよび新規追加の回帰テストがすべてパスする。

## Assumptions

- 既存の JST 暦日判定関数（`getJSTStartOfTomorrow` / `formatJSTDate`）を再利用する。
- 復習クイズおよび通常クイズの出題・回答フローのインターフェースは変更せず、内部の判定純粋関数および Server Action の修正で対応する。
