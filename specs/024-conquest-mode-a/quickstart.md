# Quickstart: 024-conquest-mode-a

実装後の手元確認。前提: ローカル Supabase、`municipality_master` 投入済み、`http://127.0.0.1:3000`、テストユーザーでログイン。

## 1. モード選択

1. `/quiz/municipality` を開く
2. A が県当て地図、B/C が練習の4択、D が場所当て地図と読める

## 2. トップの2本バー

1. モード D で政令市の1区だけ正解してトップへ戻る
2. D バーだけが増え、同市の他区は未クリアのまま（設定画面の D 進捗または未クリア優先で確認）
3. モード B または C だけ正解しても A/D バーは増えない
4. 合算%・正答率推移・苦手ランキングがトップに無い

## 3. モード D の地図

1. 政令市の区を D で出題する（北海道の札幌市区など）
2. 回答前に区が分かる
3. 出題と別の区をタップ → 不正解。出題コードはクリアにならない
4. 出題の区をタップ → そのコードが選ばれる（市全体が1面になって選べない、が起きない）

## 4. おすすめ

ロジックの分布・差し替えは Vitest（`generateRecommendation` と苦戦メタ）を正とする。画面では:

1. おすすめを開き、A または D（苦戦していなければ B/C が初手に固定されないこと）
2. A のおすすめで地方が北海道だけにならないこと
3. 1問以上答えて中断または完了し、おすすめへ戻る → 推薦が回答前のまま残らないこと

## 5. 回帰

```bash
pnpm test
pnpm type-check
```

Mode A の表示1問正規化（`toQuestionResult`）と B/C の 022 集約、SRS のモード別復習が壊れていないこと。
