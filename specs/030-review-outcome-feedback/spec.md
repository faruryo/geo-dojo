# Feature Specification: 復習完了時のSRS進捗・定着可視化

**Feature Branch**: `030-review-outcome-feedback`  
**Created**: 2026-10-02  
**Status**: Draft  
**Input**: GitHub Issue [#113](https://github.com/faruryo/geo-dojo/issues/113) 「feat(review): 復習完了時のSRS進捗・定着可視化（次回期日・卒業までの目安回数・Mode A県別明示）」  
**Related**: `specs/007-*`（復習バッチ）、`lib/quiz/srs/`（SM-2・早期卒業・同日ガード）、`specs/029-rich-answer-feedback`（直前の解答フィードバック）

---

## 前提・背景

復習モード（`/quiz/review`、最大20問のバッチ）の完了画面は、正答数・正答率・誤答一覧・今後7日の復習予定件数しか表示しない。各問題の学習ステータスが今回の回答でどう変わったか（卒業したのか、次回は何日後か、あと何回で卒業か）は見えず、復習の達成感や継続の動機を得にくい。

SM-2 実装（`lib/quiz/srs/sm2.ts` / `update.ts`）の卒業条件は次の3経路で、Ease Factor（以下 EF）による間隔の伸び方にも依存する。そのため「`4 - repetition` 回で卒業」のような単純計算は実際と食い違う。

| 経路 | 条件 |
|---|---|
| 誤答歴なし早期卒業 | 正解 かつ 対象コード×モードに誤答歴なし かつ 回答後 repetition ≥ 2 |
| 速答卒業 | quality=5（正解かつ10秒以内） かつ repetition ≥ 3 かつ interval ≥ 15 |
| 通常卒業 | repetition ≥ 4 かつ interval ≥ 30 |

例として、一度誤答した項目（EF 2.18、repetition 0、interval 1）は、通常速度で正解を続けると interval が 1 → 6 → 13 → 28 → 61 と伸びる。repetition が 4 に達しても interval が 30 未満なので、卒業は5回目の正解になる。

Mode A（都道府県当て）で複数県に同名がある市（伊達市＝北海道・福島県、池田町＝4県 等）は1問として出題されるが、保存は県ごとの代表コード単位（`dedupeInstancesByPrefecture`）で行われる。片方の県だけが卒業した場合、1問単位の表示では定着の実績が見えない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 問題ごとの次回期日と卒業状況の確認 (Priority: P1)

学習者が復習バッチを解き終えると、完了画面の詳細一覧で問題ごとに「🎉 卒業（定着達成）」「📅 次回 6日後」「🔄 明日もう一度」などのステータスを確認できる。卒業していない問題には「最速あと3回」という目安が添えられる。詳細は残り回数の少ない順にまとまる。

**Why this priority**: 今回の回答で何が変わったかを示すことが本機能の中核価値であり、ほかのストーリーはこの判定結果の上に成り立つため。

**Independent Test**: due 状態の SRS レコードを複数用意し（誤答歴あり・なし、repetition 違い）、正解・誤答を混ぜて復習を完了したとき、各行のラベルと残り回数が DB の回答後状態と SM-2 の計算に一致すること。

**Acceptance Scenarios**:

1. **Given** 誤答歴のない repetition 1 の項目, **When** 復習で正解する, **Then** 「🎉 卒業（定着達成）」と表示され、残り回数は表示されない。
2. **Given** 誤答歴のある repetition 2・interval 6・EF 2.18 の項目, **When** 復習で通常速度で正解する, **Then** 「📅 次回 13日後」と「最速あと1回」が表示される（今回の間隔は 13。以降10秒以内で正解すると次の1回で卒業）。
3. **Given** reviewing の項目, **When** 復習で誤答する, **Then** 「🔄 明日もう一度」と、リセット後の状態から算出した残り回数が表示される。
4. **Given** 回答前に卒業済みだった行（Mode A の同名別県など）, **When** 誤答する, **Then** 「⚠️ 復習に戻りました（明日もう一度）」と表示される。
5. **Given** 回答前に卒業済みだった行, **When** 正解して卒業状態が続く, **Then** 「🎓 定着維持」と表示される。
6. **Given** 同じ JST 暦日に既に正解して期日が明日以降に進んでいる行, **When** 再び正解する（同日ガードで SRS が更新されない）, **Then** 「⏸️ 同日回答済み」と表示される。
7. **Given** 次回期日が JST の同じ暦日・翌日・N日後, **When** 結果を表示する, **Then** それぞれ「📅 次回 今日」「📅 次回 明日」「📅 次回 N日後」と表示される（時間差の切り上げではなく JST 暦日差で判定）。

### User Story 2 - バッチ全体の定着サマリ (Priority: P1)

学習者は完了画面の上部で「🎉 定着 3件 / 🔄 復習継続 16件 / ⚠️ 保存失敗 1件」のように、今回のバッチで何問が定着したかをひと目で把握できる。

**Why this priority**: 詳細一覧を開かなくても成果がわかる要約であり、US1 と同じ判定から1問1件で集計するだけなので同時に提供する。

**Independent Test**: 20問のバッチで、定着・復習継続・保存失敗の件数の合計が回答した問題数（結果画面の分母）と常に一致すること。

**Acceptance Scenarios**:

1. **Given** 1問1行の問題（Mode B/C/D）, **When** 回答後の状態が卒業, **Then** その問題は「定着」に数えられる。
2. **Given** Mode A で2県に分かれる問題, **When** 片方の県だけ卒業した, **Then** その問題は「復習継続」に数えられる（全県が卒業したときだけ「定着」）。
3. **Given** 保存に失敗した問題, **When** 集計する, **Then** その問題は「保存失敗」に数えられ、定着・復習継続には含まれない。
4. **Given** 任意のバッチ, **When** サマリを表示する, **Then** `定着 + 復習継続 + 保存失敗 = 回答した問題数` が必ず成り立つ。保存失敗が0件のときはその項目を表示しない。

---

### User Story 3 - Mode A 同名多県の県別ステータス明示 (Priority: P2)

Mode A で複数県に同名がある問題は、詳細一覧で県ごとの行に分けて表示する（例: 伊達市 → 北海道「🎉 卒業（定着達成）」、福島県「📅 次回 6日後」）。どの県が定着し、どの県が残っているかがわかる。

**Why this priority**: 1問単位の表示では片方の県の定着が隠れるという Issue の課題3を解消する。対象は Mode A の同名多県の問題に限られるため P2 とする。

**Independent Test**: 伊達市（北海道・福島県）の Mode A 問題で、県ごとに異なる SRS 状態を用意して回答したとき、県別の行に異なるラベルが出て、サマリでは1問として数えられること。

**Acceptance Scenarios**:

1. **Given** Mode A の同名2県の問題, **When** 回答する, **Then** 詳細一覧では問題名の下に県ごとの行が並び、それぞれの県のラベルと残り回数が表示される。
2. **Given** 政令指定都市（例: 札幌市＝10区）を含む Mode A の問題, **When** 回答する, **Then** 区ごとの行は作られず、保存と同じ県別代表コード1件ぶんの行だけが表示される。

### User Story 4 - 取得失敗時の安全なフォールバック (Priority: P2)

回答前後の SRS 状態を取得できなかった場合や、保存結果と問題の対応が取れなかった場合、完了画面は従来どおりの表示（正答数・誤答一覧・復習予定）にフォールバックし、誤った成果を表示しない。

**Why this priority**: 誤った「卒業」表示は学習者の判断を誤らせる。表示しないほうが安全なので、取得失敗時の挙動を明確にする。

**Independent Test**: 回答前の状態取得を失敗させたとき、回答後の状態取得を失敗させたとき、保存メタ情報の件数や番号を壊したときに、それぞれ従来の結果画面が表示され、クイズの進行や結果保存は妨げられないこと。

**Acceptance Scenarios**:

1. **Given** 回答前の状態取得が失敗した, **When** 復習を開始する, **Then** クイズは通常どおり開始・進行・保存され、完了画面は従来表示になる。
2. **Given** 回答後の状態取得が失敗した, **When** 完了画面を表示する, **Then** 従来の誤答一覧（「まだ苦手な市区町村」）を表示する。
3. **Given** 保存メタ情報の件数・問題番号・コード集合が出題と一致しない, **When** 完了画面を表示する, **Then** 成果表示を行わず従来表示にする。
4. **Given** 完了画面で「続けて復習する」を押して次のバッチを開始した, **When** 前のバッチの回答後状態の取得が遅れて返ってきた, **Then** その結果は捨てられ、新しいバッチの画面を上書きしない。

---

### Edge Cases

- **回答前の状態が存在しない行**: Mode A の同名別県は、その県のレコードがまだ無いことがある。回答前の状態を「レコードなし（reviewing・誤答歴なし）」として扱い、正解で卒業すれば「🎉 卒業（定着達成）」、そうでなければ「📅 次回 N日後」とする。
- **速答（10秒以内）による卒業**: 速答卒業は実際の回答後状態（DB）で判定されるので、ラベルは「🎉 卒業（定着達成）」になる。残り回数の目安は、これから毎回10秒以内（quality=5）で正解し続けた回数で、「最速あとN回」と表示する。誤答歴がなければ早期卒業が先に届くので回数は変わらない。誤答歴があれば短くなる（EF 下限 1.3 の 9 回は 4 回）。
- **シミュレーションの上限**: 壊れたデータ（EF が NaN など）に備えて上限20回で打ち切る。上限に達したら「最速20回以上」と表示し、この問題は「あとN回」のまとまりに入れない。
- **件数上限**: 1回の状態取得は最大100件とする。20問のバッチで Mode A の同名多県（最大4県）が多く含まれても通常は収まるが、超える場合は成果表示を行わず従来表示にする。
- **同日の重複**: 同じ問題が別タブなどで同日に既に正解・前進済みの場合は「⏸️ 同日回答済み」とする。サマリは回答後の状態で分類する（卒業済みなら定着）。
- **中断**: 途中で中断した場合は完了画面に遷移しないため、成果表示は行わない（既存挙動を維持）。
- **保存失敗**: 結果の保存（単一トランザクション）が失敗した問題は、回答後状態の取得対象から外し、行・サマリともに「⚠️ 保存失敗」とする。保存は全件成功か全件失敗のどちらかなので、Mode A の同じ問題内で県によって成否が分かれることはない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (回答前状態の確定)**: 復習バッチの出題を組み立てた後、出題開始前に、各問題で保存されるコード×モードの集合（Mode A は `dedupeInstancesByPrefecture` による県別代表コード、B/C/D は出題コード）について SRS の状態と誤答歴を取得し、取得が完了してから出題を開始しなければならない。回答後の状態を回答前と誤読するレースを防ぐためである。
- **FR-002 (コード集合の一致)**: 回答前の状態取得、結果保存、回答後の状態取得の3か所で扱うコード×モードの集合は完全に一致しなければならない。一致しない問題があれば、そのバッチ全体で成果表示を行ってはならない。
- **FR-003 (状態取得の検証)**: 状態取得はログイン中ユーザーのデータに限定し、モードは `A`/`B`/`C`/`D` のみ、コードは5桁の数字、1回あたり最大100件で受け付けなければならない。範囲外の入力は拒否しなければならない。
- **FR-004 (保存成否の受け渡し)**: クイズ実行部は、完了時に表示用結果に加えて、問題ごとの保存メタ情報（問題番号・保存成否・モード・正誤・保存したコード一覧）を完了コールバックへ渡さなければならない。既存の呼び出し側（通常クイズ）はこの追加引数を無視しても従来どおり動作しなければならない。
- **FR-005 (行ラベルの排他決定)**: 行（コード×モード）ごとに、次の優先順で1つだけラベルを決めなければならない。
  1. 保存失敗 → 「⚠️ 保存失敗」
  2. 正解 かつ 保存時に同日ガードで SRS が更新されなかった（回答前の取得後に別タブで前進した場合を含む）、または回答前のレコードがあり最終回答日時が変わっていない → 「⏸️ 同日回答済み」
  3. 誤答 かつ 回答前が卒業 → 「⚠️ 復習に戻りました（明日もう一度）」
  4. 誤答 → 「🔄 明日もう一度」
  5. 回答後が卒業 かつ 回答前も卒業 → 「🎓 定着維持」
  6. 回答後が卒業 → 「🎉 卒業（定着達成）」
  7. 上記以外 → 「📅 次回 N日後」（JST 暦日差が0以下なら「今日」、1なら「明日」、2以上なら「N日後」）
- **FR-006 (卒業までの目安回数)**: 回答後が卒業でなく保存に成功した行について、回答後の EF・repetition・interval と「実効誤答歴 = 回答前の誤答歴 OR 今回誤答」を入力に、毎回10秒以内（quality=5）で正解を続けた場合に何回目で卒業するかを、SM-2 と早期卒業・速答卒業をそのまま再現する純粋関数で算出し、「最速あと○回」と表示しなければならない。上限は20回とし、到達しない場合は「最速20回以上」と表示しなければならない。卒業済みの行には表示してはならない。
- **FR-013 (詳細の並び)**: 「問題ごとの結果」は表示時だけ並べ替える。保存順とサマリ集計は変えない。残り回数がある問題は、県のうち一番少ない回数のまとまりに問題ごと置き、見出しは「あとN回 M問」とする。同じ回数の中は出題順。0件の回数は出さない。複数県の行は分けず、行の右にそれぞれの回数を出す。「最速20回以上」だけの問題は見出しを付けず、回数のまとまりの後・卒業の前に置く。その後に「卒業 M問」、最後に「保存失敗 M問」。どちらも0件なら出さない。各行は左が県とラベル、右が残り回数。
- **FR-007 (サマリの1問1件集計)**: サマリは問題単位で、保存失敗なら「保存失敗」、全行が卒業なら「定着」、それ以外は「復習継続」に分類し、`定着 + 復習継続 + 保存失敗 = 回答した問題数` を保証しなければならない。表記は「定着 3件」の形式とし、「+3」のような符号は使わない。
- **FR-008 (フォールバック)**: 回答前・回答後の状態取得の失敗、保存メタ情報の不整合（件数が結果数と違う、問題番号が範囲外・重複、コード集合が出題と違う）、件数上限超過のいずれかが起きた場合は成果表示を行わず、従来の誤答一覧を表示しなければならない。状態取得の失敗はクイズの開始・進行・保存を妨げてはならない。
- **FR-009 (古い応答の破棄)**: 回答後状態の取得結果は、そのバッチがまだ表示中の場合にだけ画面へ反映し、次のバッチ開始後に返ってきた応答は捨てなければならない。
- **FR-010 (画面構成)**: 完了画面は、上から「正答数・正答率」「成果サマリ」「操作ボタン（続けて復習・おすすめ・ダッシュボード）」「問題ごとの詳細（初期状態は閉じたアコーディオン）」「今後7日の復習予定」の順に並べなければならない。成果を表示している間（取得中を含む）は誤答一覧を出さず、フォールバック時だけ従来の誤答一覧を出す。
- **FR-011 (結果カードの拡張)**: 共通の結果カードに、操作ボタンの下へ任意の内容を差し込める領域を追加しなければならない。この領域を使わない既存画面の表示は変わってはならない。
- **FR-012 (表示とモバイル)**: 成果サマリと詳細一覧は幅375px・ダークモードで横スクロールなしに表示でき、詳細の各行は問題名（Mode A 多県は県名つきの行）・ラベル・残り回数を折り返して読めなければならない。

### Key Entities

- **SRS スナップショット**: あるユーザーの1コード×1モードについて、ある時点の SRS 状態（EF・repetition・interval・status・次回期日・最終回答日時。レコードが無ければ空）と誤答歴の有無。回答前と回答後の2回取得する。
- **保存メタ情報（QuestionSaveMeta）**: 1問ごとの問題番号・保存成否・モード・正誤・保存したコード一覧・同日ガードで SRS を更新しなかったコード一覧。クイズ実行部から完了画面へ渡す。
- **復習成果（ReviewOutcome）**: 問題ごとの分類（定着・復習継続・保存失敗）と行ごとのラベル・残り回数、およびサマリ件数。画面表示専用で永続化しない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 復習完了画面で、保存に成功した全行のラベルが DB の回答後状態と一致する（卒業・期日・同日ガードの判定が100%一致）。
- **SC-002**: 「最速あと○回」の目安は、同じ初期状態から10秒以内の正解を続けた場合に SM-2 実装が実際に卒業させる回数と100%一致する（誤答歴あり・なし、EF 下限を含むケース表で検証）。
- **SC-003**: すべてのバッチで `定着 + 復習継続 + 保存失敗 = 回答した問題数` が成り立ち、Mode A の同名多県の問題も1問として数えられる。
- **SC-004**: 状態取得の失敗やメタ情報の不整合が起きても、クイズの開始・進行・結果保存の成功率は変わらず、完了画面は従来表示で必ず描画される。
- **SC-005**: 幅375pxのダークモードで、20問ぶんの詳細一覧（Mode A 4県の問題を含む）が横スクロールなしに表示される。
- **SC-006**: 完了画面の表示は回答後状態の取得を待たずに始まり、取得中は成果サマリの位置にスケルトンを出して、取得完了時にレイアウトが大きく動かない。

---

## Assumptions

- DB スキーマの変更は行わない。既存の `srs_records`（EF・repetition・interval・status・due_date・last_reviewed_at）と `municipality_quiz_results`（誤答歴）から取得できる。
- 結果保存（`saveMunicipalityQuizResults`）は1問ぶんを単一トランザクションで行い、失敗時は throw するので、問題単位の保存成否は `persisted` で判別できる。SRS 更新もこのトランザクション内で行われるため、保存成功なら回答後の SRS 状態は確定している。
- 完了コールバックが呼ばれる時点で、全問の保存は完了している（`recordAndAdvance` は保存完了後にだけ次問へ進む。スキップ要求も保存完了まで保留される）。
- 復習の出題対象（due）は status が reviewing のレコードだけである。回答前に卒業済みの行が現れるのは、Mode A で同名の別県が一緒に保存される場合に限られる。
- 「今日・明日・N日後」の基準時刻は完了画面を描画したクライアントの現在時刻とし、JST の暦日差で判定する。
- 通常のクイズ（`/quiz/municipality/[mode]`）の完了画面は本機能の対象外とし、表示を変えない。
