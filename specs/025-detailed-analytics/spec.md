# Feature Specification: 詳細分析ページ（ダッシュボードから外す学習データの集約）

**Feature Branch**: `025-detailed-analytics`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "詳細分析ページ: ダッシュボードから外す学習データを移す。024でトップをシンプルにしたため、学習の内訳（正答率推移・苦手市区町村ランキング・B/C練習クリア数・学習統計など）をトップを汚さずに見られる場所を作る。"

## Clarifications

### Session 2026-09-01

- Q: 詳細分析ページへのアクセス導線は、ボトムナビゲーションに「分析」タブを追加する構成でよいですか？ → A: ボトムナビに4つ目のタブとして「分析」（`/analytics`）を追加する。トップ画面はスリム化を維持しリンクカード等は置かない。
- Q: 詳細分析画面内のコンテンツ（サマリー、フィルター、推移グラフ、苦手ランキング、モード別進捗）の配置構成は、縦スクロールの1画面構成でよいですか？ → A: 縦スクロール1画面にサマリー、フィルター、推移グラフ、モード別進捗、苦手ランキングを配置する。
- Q: 上部サマリーカードの4つの表示指標はどうしますか？ → A: 「累計出題数」「全体正答率」「県当て(A)制覇率」「場所当て(D)制覇率」とする。
- Q: フィルターバーや各種ラベルで表示するモード名表記はどうしますか？ → A: 024命名規則に統一し、「全て」「県当て(A)」「県当て練習(B)」「市当て練習(C)」「場所当て(D)」とする。
- Q: フィルターバーで「地方」や「モード」「期間」を切り替えた際、下部の「苦手ランキング」は連動して絞り込みますか？ → A: フィルターバーの期間・地方・モード選択と連動し、選択中の条件に合致する苦手市区町村のみをサーバー側で絞り込んでから上位順に表示する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 学習データの詳細内訳（推移・苦手・モード別進捗）を見る (Priority: P1)

学習者は専用の「詳細分析」画面を開き、トップ画面（おすすめと制覇）には置かない学習サマリー（累計出題数・全体正答率・県当て(A)制覇率・場所当て(D)制覇率）、正答率推移グラフ、苦手市区町村ランキング、モード別（A:県当て, B:県当て練習, C:市当て練習, D:場所当て）および難易度別の練習クリア状況を一覧（縦スクロール1画面）で確認できる。

**Why this priority**: 024でトップ画面を薄くした結果、学習進捗や苦手傾向の振り返り情報が隠れてしまわないようにするための受皿となる主要画面だから。

**Independent Test**: クイズをプレイ済みの学習者アカウントで詳細分析画面を開き、4サマリーカード・正答率推移グラフ・モード別クリア状況・苦手市区町村リストが1画面内でスクロールして閲覧できることを確認する。

**Acceptance Scenarios**:

1. **Given** 1回以上のクイズプレイ履歴がある学習者, **When** 詳細分析画面を開く, **Then** 上部サマリーカード（累計出題数、全体正答率、県当て(A)制覇率、場所当て(D)制覇率）、正答率推移グラフ、モード別（A/B/C/D）の難易度別クリア進捗、苦手市区町村ランキングが縦スクロールで配置された1画面が表示される。
2. **Given** まだ1問もクイズを解いていない新規学習者, **When** 詳細分析画面を開く, **Then** エラーにならず「まだデータがありません」等の分かりやすい初期状態メッセージとクイズ開始への誘導が表示される。
3. **Given** 詳細分析画面を開いたとき, **When** モード別の消化状況を見る, **Then** 本番モード（県当て(A), 場所当て(D)）だけでなく練習モード（県当て練習(B), 市当て練習(C)）のクリア数・進捗も確認できる。

---

### User Story 2 - 条件（期間・地方・モード）を絞り込んで学習状況を分析する (Priority: P2)

学習者は詳細分析画面で期間（全期間、直近7日、直近30日など）や地方・モードを選択してフィルターをかけ、特定の学習スコープに絞った正答率推移や苦手自治体を確認できる。

**Why this priority**: 全期間の合算だけでなく、「今週の成果」や「苦手な東北地方に絞ったデータ」を確認できることで学習のモチベーションと自己分析の質が向上する。

**Independent Test**: フィルターバーで期間（7日/30日/全期間）や特定の地方・モードを選択した際、推移グラフと苦手ランキングの表示内容が連動して更新されることを確認する。

**Acceptance Scenarios**:

1. **Given** 複数期間・複数地方のプレイ履歴がある学習者, **When** 期間フィルターを切り替える（例: 直近7日）, **Then** 指定期間内の回答データに基づいた推移グラフおよび指定期間に絞り込んだ苦手ランキングが表示される。
2. **Given** 特定の地方やモードに絞り込んだとき, **When** 苦手ランキングを見る, **Then** 選択した期間・地方・モードでサーバー側絞り込みが行われ、合致する市区町村の上位ランキングが表示される。
3. **Given** 選択したフィルター条件に合致する回答データが0件のとき, **When** 画面を見る, **Then** 該当データがない旨が分かりやすく表示される。

---

### User Story 3 - ナビゲーションからスムーズに詳細分析画面へ移動する (Priority: P1)

学習者はアプリ共通のボトムナビゲーションに配置された「分析」タブから迷わず詳細分析画面（`/analytics`）に移動し、ホーム画面（`/`）や他のクイズ画面へ自由に行き来できる。トップ画面はスリム化を維持する。

**Why this priority**: 画面が作られても導線がなければユーザーがアクセスできないため。

**Independent Test**: ボトムナビの「分析」タブをタップして詳細分析画面に遷移し、ボトムナビの「ホーム」タブでトップ画面に戻れることを確認する。

**Acceptance Scenarios**:

1. **Given** アプリの任意の主要画面にいるとき, **When** ボトムナビゲーションの「分析」タブをタップする, **Then** 詳細分析画面（`/analytics`）へ遷移し、タブのアクティブ状態が「分析」に切り替わる。
2. **Given** 詳細分析画面にいるとき, **When** ボトムナビの「ホーム」タブをタップする, **Then** トップ（ダッシュボード）画面へ遷移する。

---

### Edge Cases

- **未プレイ（データ0件）のユーザー**: グラフやランキング領域でNaNや描画エラーを起こさず、適切なEmptyStateメッセージとクイズへのアクションボタンを表示する。
- **回答数が極端に少ない場合**: 苦手ランキング（例: 1問中1問不正解で誤答率100%）の表示において、回答回数と誤答率が明瞭に伝わる表示を行う。
- **A/D制覇率の計算単位**:
  - 県当て(A)制覇率は、024確立仕様通り出題対象の一意市区町村名単位（`name` 単位、除外対象適用後）で算出する。
  - 場所当て(D)制覇率は、5桁市区町村コード単位（`code` 単位）で算出する。
- **同名・複数県（伊達市など）**:
  - Mode A の同名市出題では複数県レコードが保存されるが、累計出題数・正答率・推移グラフ・難易度別進捗の集計では同一出題を1件として正規化して算出し、過大カウントを防ぐ。
  - 新規保存時は Server Action（`saveMunicipalityQuizResults`）側で単一のサーバー時刻（`answeredAt`）を一括付与して保存し、各レコードに対して `upsertSrsRecord` による SRS 更新を漏れなく実行する。
  - 過去履歴（個別タイムスタンプで保存されたレガシーレコード）については、同一ユーザー・同一自治体名・同一モードAで回答時刻が2秒以内のレコードを同一出題として集約する。
  - Mode A 同名市の複数県インスタンスが異なる難易度バケットに属する場合、推移グラフおよび難易度別進捗（母集団・クリア数）の集計において `representativeDifficulty()`（最も難しい難易度）を採用して1つの難易度系列に割り当てる。
  - 苦手市区町村ランキングで同名市がある場合、都道府県名が併記されて正しく区別できること。
- **政令指定都市の区**: モードD等で区単位のデータがある場合、区名が正しく表示されること。
- **特定地方/モードの苦手データが全体上位20件に含まれない場合**: クライアント側の単なるスライスではなく、サーバークエリにフィルター条件を渡して絞り込んでからソート・リミットすることで、選択条件に合致する苦手市区町村が確実に表示されること。
- **モバイル画面（幅375px）**: 横スクロールのはみ出しやレイアウト崩れがなく、縦スクロールでストレスなく閲覧できること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは詳細分析画面（`/analytics`）を提供し、認証済みユーザーが自身の学習データを閲覧できるようにしなければならない。
- **FR-002**: 詳細分析画面は、期間に応じた粒度（直近7日/30日は日別、全期間は週別または日別）の正答率推移を視覚的な時系列チャートで表示しなければならない。
- **FR-003**: 詳細分析画面は、誤答率の高い市区町村を上位順に並べた「苦手市区町村ランキング」を表示し、フィルターバーの期間・地方・モード選択と連動してサーバー側で絞り込みの上で上位順に表示しなければならない。
- **FR-004**: 詳細分析画面は、モード別（A:県当て, B:県当て練習, C:市当て練習, D:場所当て）および難易度別のクリア状況・進捗（クリア数・クリア率）を表示しなければならない。
- **FR-005**: 詳細分析画面は、期間（全期間 / 直近30日 / 直近7日等）および地方・モードによるデータ絞り込み機能を提供しなければならない。
- **FR-006**: アプリ共通のボトムナビゲーション（`BottomNav`）に「分析」（`/analytics`）タブを追加し、各画面から詳細分析画面へのアクセスを可能にしなければならない。
- **FR-007**: 詳細分析画面のレイアウトは縦スクロールの1画面構成とし、上部サマリー（累計出題数、全体正答率、県当て(A)制覇率、場所当て(D)制覇率） → フィルター & 推移グラフ → モード・難易度別クリア状況 → 苦手ランキングの順に配置しなければならない。
- **FR-008**: 学習履歴が存在しない場合は、プレースホルダーや初期状態案内（Empty State）を表示しなければならない。
- **FR-009**: 画面デザインは幅375pxを基準とするモバイル端末に最適化し、デフォルトのダークモード（`#111111`基調）に準拠しなければならない。
- **FR-010**: トップ画面（`/`）には詳細分析用のグラフや苦手ランキングを直接配置せず、トップ画面の役割（おすすめと制覇の提示）と分離を維持しなければならない。

### Key Entities

- **学習分析サマリー (Analytics Summary)**: 累計出題数、全体正答率、県当て(A)制覇率（名前単位）、場所当て(D)制覇率（コード単位）。
- **正答率推移 (Accuracy Trend)**: 日付・週ごとの回答数と正答率の時系列データセット。
- **苦手自治体 (Weakness Ranking Item)**: 市区町村コード、市区町村名、都道府県名、総出題回数、不正解回数、誤答率。
- **分析フィルター (Analytics Filter)**: 期間（period: 7d, 30d, all）、地方（region）、モード（mode: all, A, B, C, D）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: クイズプレイ履歴があるユーザーが詳細分析画面にアクセスした際、3秒以内に全データ（推移、苦手、モード別サマリー）が描画される。
- **SC-002**: 絞り込み条件（期間・地方・モード）を変更した際、1秒未満で画面のグラフ・ランキングが連動更新される。
- **SC-003**: 未プレイのユーザーがアクセスした際、エラーを発生させずに100%初期ガイダンスUIが表示される。
- **SC-004**: 幅375pxの画面幅において、水平スクロールバーやUIの見切れ・重複が一切発生しない。
- **SC-005**: トップ画面（ダッシュボード）と詳細分析画面の役割が明確に分離され、トップ画面の初回読み込み軽量性が維持される。

## Assumptions

- 既存のDBスキーマ（`municipality_quiz_results`, `municipality_master`, `srs_records`）に蓄積されているデータを利用し、新たなDBテーブルは追加しない。
- Mode A 同名市の複数行保存時は Server Action 側で単一のサーバー時刻を付与してバッチ保存し、同時に各レコードの `upsertSrsRecord` を実行する。
- 既存のダッシュボード用コンポーネント（`AccuracyChart`, `WeaknessRanking`, `DifficultyProgress`, `SummaryCards`, `FilterBar`）およびクエリ関数の資産を再利用・再構成して詳細分析画面を構築する。
- ナビゲーションの構成はボトムナビゲーションへの「分析」タブ追加（`/analytics`）により実現する。

## Out of Scope

- 新規集計用DBテーブルの作成やバッチ集計基盤の導入。
- 024で定義されたおすすめロジックやA/D制覇の計算ルールの変更。
- 外部エクスポート機能（CSV出力等）。
- ソーシャル共有やフレンドランキング機能。
