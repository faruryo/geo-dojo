# Feature Specification: Mode D（順引き地図）市区町村出題選択・絞り込み

**Feature Branch**: `faruryo/feat-mode-d`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "https://github.com/faruryo/geo-dojo/issues/73 Mode D（順引き地図）で市区町村単位の出題選択・絞り込みを可能にする"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 都道府県単位での集中学習 (Priority: P1)

ユーザーは Mode D（順引き地図）の設定画面で、従来の「地方（関東、近畿など）」だけでなく「特定の都道府県（例: 東京都、長野県、福岡県など）」を直接指定して、その都道府県内の市区町村だけに絞って出題・練習したい。

**Why this priority**:
Mode D は都道府県地図上のポリゴンを直接探索してタップするゲーム性のため、特定の都道府県を集中的にマスターしたいという学習ニーズが最も高く、機能の基礎となるため最優先（P1）。

**Independent Test**:
設定画面で特定の都道府県（例: 「長野県」）を選択してクイズを開始すると、出題される市区町村がすべて長野県内の自治体となり、正しく地図上で回答できることで検証できる。

**Acceptance Scenarios**:
1. **Given** ユーザーが Mode D 設定画面を開いている, **When** 都道府県選択で「長野県」を選択する, **Then** 出題対象プールが長野県内の市区町村に絞り込まれ、進捗バーと件数が長野県の母数に更新される。
2. **Given** 「長野県」が選択された状態, **When** クイズを開始する, **Then** 長野県内の市区町村名が出題され、長野県の地図上で正解位置をタップして回答できる。

---

### User Story 2 - 都道府県内の市区町村個別選択・除外 (Priority: P2)

ユーザーは特定の都道府県を選択した上で、その都道府県内の市区町村一覧から「特定の自治体のみを選択」または「特定の自治体を除外」して、苦手な自治体や覚えたい自治体グループだけに絞ったカスタム特訓を行いたい。

**Why this priority**:
「市部だけ」「郡部町村だけ」「苦手な5市だけ」など、学習深度に応じた柔軟な特訓を可能にするため。

**Independent Test**:
都道府県選択後に自治体一覧を展開し、特定の3自治体のみにチェックを入れて開始すると、その3自治体のみから問題が構成されることで検証できる。

**Acceptance Scenarios**:
1. **Given** ユーザーが特定の都道府県を選択している, **When** 市区町村選択パネルを開く, **Then** その都道府県に属する全市区町村が一覧表示され、各自治体の名称・難易度・クリア状態が確認できる。
2. **Given** 市区町村一覧が表示されている, **When** 「全選択」「全解除」ボタンをタップする, **Then** 一覧内の全自治体の選択状態が一括で切り替わる。
3. **Given** ユーザーが数件の自治体のみを選択している, **When** クイズを開始する, **Then** 選択された自治体のみが出題対象となる。

---

### User Story 3 - 既存学習オプション（未クリア優先・苦手優先・難易度）との連動 (Priority: P2)

ユーザーが都道府県や個別自治体を絞り込んだ状態でも、既存の「難易度絞り込み」「未クリア優先」「苦手優先」および「問題数（10/20/30問）」のオプションが指定プール内で矛盾なく適用されること。

**Why this priority**:
カスタムプール内でも SRS / 忘却曲線や未学習優先の学習効率化ロジックをシームレスに機能させるため。

**Independent Test**:
特定都道府県の未クリア優先を有効にしてクイズを開始した際、指定都道府県内の未クリア自治体が最優先で出題されることで検証できる。

**Acceptance Scenarios**:
1. **Given** 特定都道府県と「入門・中級」難易度が選択されている, **When** 出題プールが計算される, **Then** 指定都道府県かつ指定難易度に合致する自治体のみが出題対象となる。
2. **Given** 「未クリア優先」が有効, **When** クイズが生成される, **Then** カスタムプール内の未クリア自治体がクリア済み自治体よりも優先して出題される。

---

### User Story 4 - 選択状態の URL 保持とリプレイの再現性 (Priority: P3)

ユーザーがクイズを完了した後の「もう一度」「同じ設定でもう一度」や、URL のブックマーク・共有時に、選択していた都道府県や市区町村の絞り込み状態が維持されること。

**Why this priority**:
反復練習時の UX を高め、設定の再入力を不要にするため。

**Independent Test**:
クイズ終了画面で「もう一度」を押した際、設定画面に戻ることなく同一のカスタムプールで即座に新しいセッションが開始されることで検証できる。

**Acceptance Scenarios**:
1. **Given** カスタムプールでのクイズが終了した, **When** 「もう一度」ボタンを押す, **Then** 最新の習得状態を取得し直した上で同一のカスタム設定で再出題される。
2. **Given** URL に都道府県やカスタムコードが含まれる, **When** ユーザーがページを直接開く, **Then** 指定された都道府県・自治体が初期選択された状態で設定画面が表示される。

---

### Edge Cases

- **選択件数が 0 件の場合**: 市区町村のチェックがすべて外れている場合（`selectedCodes: []`）、出題プール数は 0 件となり、スタートボタンは disabled となる。
- **選択件数がセッション問題数（例: 10問）未満の場合**: 選択された自治体数（例: 3件）が問題数より少なくても開始可能とする。同一セッション内での重複出題を避け、プール内の全件（3問）でセッションが構成され、設定画面で「該当 3 件のみ — 全 3 問で出題されます」の案内を表示する。
- **都道府県を変更した場合**: 都道府県を切り替えた際、以前の県の個別自治体選択はリセットされ、新しく選択された県の全自治体がデフォルトで選択状態となる（意図しない混在を防ぐ）。
- **政令指定都市の扱い**: Mode D において政令指定都市は各「区」（例: 静岡市葵区、大阪市北区等）ごとに独立した地図ポリゴンと自治体コードを持つ。一覧では区単位で選択可能とし、親市単位のグルーピングまたは検索/視認性を担保する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは Mode D 設定画面において、従来の地方単位に加えて「都道府県単位」での出題対象指定を可能にしなければならない（MUST）。
- **FR-002**: システムは都道府県が選択された際、その都道府県に属する市区町村の一覧を展開・選択できる UI を提供しなければならない（MUST）。
- **FR-003**: 市区町村一覧 UI は、「全選択」「全解除」の一括操作機能を提供しなければならない（MUST）。
- **FR-004**: 市区町村一覧 UI は、各自治体の「名称」「よみがな」「難易度バッジ」「クリア済みステータス」を視認可能に表示しなければならない（MUST）。
- **FR-005**: 市区町村一覧 UI は、自治体数が多い都道府県（例: 北海道や長野県など）でも素早く目的の自治体を見つけられるよう、名称/かな検索またはフィルタリングをサポートしなければならない（MUST）。
- **FR-006**: クイズ出題サンプリングロジックは、指定された都道府県および個別選択された自治体コードのリスト（カスタムプール）を正確に受け取り、その中から出題問題を生成しなければならない（MUST）。
- **FR-007**: カスタムプール指定時も「未クリア優先」「苦手優先」「難易度フィルタ」が指定プール内の母集団に対して正しく適用されなければならない（MUST）。
- **FR-008**: 設定画面の進捗バー（`QuizPoolProgress`）およびプール件数は、選択された都道府県・個別自治体の母数とクリア数にリアルタイムに連動して表示されなければならない（MUST）。
- **FR-009**: 都道府県および選択自治体の状態は URL クエリパラメータ（例: `pref`, `codes` 等）に反映・復元可能でなければならない（MUST）。
- **FR-010**: クイズ完了時の「もう一度」実行時および設定画面への戻り操作時、カスタムプールの設定内容が保持されなければならない（MUST）。
- **FR-011**: モバイル画面（幅 375px）において、自治体一覧の選択 UI が画面外にはみ出さず、スクロールやタップ操作が快適に行えなければならない（MUST）。

### Key Entities

- **MunicipalityScopeFilter**: 出題範囲の指定構造体。
  - `type`: `'region'`（地方単位） | `'prefecture'`（都道府県単位）
  - `regions`: `Region[]`（地方選択時の配列）
  - `prefecture`: `string | null`（都道府県選択時の県名）
  - `selectedCodes`: `string[] | null`（個別選択された自治体コード群。null/空の場合は県内全件）
- **MunicipalityQuizSettings**: 拡張されたクイズ設定。
  - 既存の `mode`, `count`, `unclearedFirst`, `weaknessFirst`, `difficulties` に加え、上記の範囲フィルタ条件を包含。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは設定画面から 3 タップ以内で任意の都道府県を選択し、その県単独のクイズを開始できる。
- **SC-002**: 自治体数が 50 以上の都道府県でも、全選択・全解除および個別選択の切り替えが 100ms 以内で即時 UI に反映される。
- **SC-003**: カスタム選択した自治体プールからの出題で全問回答完了後、正誤判定・クリア情報（`municipality_quiz_results` / `srs_records`）が正確に DB に記録され、「もう一度」で同一設定で即座に再開できる。
- **SC-004**: 幅 375px のモバイル環境で、自治体一覧モーダル/ドロワーまたはアコーディオンが破綻なく操作できる。

## Assumptions

- Mode D（順引き地図）を主要ターゲットとして設計・実装するが、内部のデータフィルタ関数（`filterByPrefecture`, `filterByCodes` 等）は他モードでも再利用可能な純粋関数として構築する。
- Mode D は単一の都道府県地図をレンダリングするため、都道府県単位の絞り込み時は 1 つの都道府県が選択されることを基本とする。
- 地方単位選択（例: 「関東」）時は従来の地方単位全自治体プールが出題対象となる。
- 自治体コード（JIS 5桁コード）を自治体の一意キーとして使用する。
