# municipality-quiz Specification

## Purpose
市区町村クイズ（モード A / B / C / D）の出題・判定・回答直後のフィードバック・結果保存・制覇進捗を定める。
4 つのモードは「何を問うか」「何を単位に出題・保存・制覇を数えるか」が異なるので、その単位の取り違えを起こさないことを保証する。
特に Mode A の同名市は 1 問で出題して県ごとに保存し、表示は 1 問 1 件に正規化する。Mode D は政令市の区を含むコード単位で扱う。東京 23 区は Mode A / B / C の出題と制覇率の母数から外す。
各クイズ共通の進行（HUD、タイマー、回答時間の記録、効果音、中断確認、紙吹雪、結果画面の共通部分、キーボード操作）は `quiz-session`、回答後の SRS 更新は `srs-review`、マスタの内容（人口・難易度・政令市・東京 23 区の定義）は `municipality-master`、おすすめからの自動開始は `recommendation` を参照する。

## Requirements

### Requirement: クイズ選択とモード選択
システムは、クイズ選択画面（`/quiz`）から都道府県クイズと市区町村クイズの 2 つへ入れるようにし、市区町村クイズのモード選択画面（`/quiz/municipality`）で Mode A / B / C / D を 1 つ選んで各モードの設定画面（`/quiz/municipality/<mode>`）へ進めなければならない (SHALL)。モード選択画面は、選択中のモードのプレビューと、出題ルール（同名除外・同名市の集約）の説明を CTA より後ろに置かなければならない (SHALL)。URL のモード指定は大文字小文字を区別しないが、A〜D 以外のモードを指す設定画面の URL は 404 としなければならない (SHALL)。

#### Scenario: モードを選んで設定画面へ進む
- **WHEN** モード選択画面でモード C を選んで「このモードで遊ぶ」を押したとき
- **THEN** `/quiz/municipality/c` の設定画面へ遷移する

#### Scenario: 無効なモードの URL
- **WHEN** `/quiz/municipality/e` を開いたとき
- **THEN** 設定画面は表示されず 404 になる

### Requirement: 最後に選んだモードの記憶
システムは、選んだモードを localStorage（`geo-dojo:last-selected-mode`）に保存し、モード選択画面の初期選択を「URL の `mode` パラメータ、保存済みモード、既定の Mode B」の優先順で決めなければならない (SHALL)。モードの設定画面に入ったときも、有効なモードであれば同じキーへ保存しなければならない (SHALL)。保存値が A〜D（大文字小文字不問）以外のとき、および localStorage が使えないときは、保存値を無視して動作を続けなければならない (SHALL)。

#### Scenario: 保存済みモードで開く
- **WHEN** 以前 Mode D を選んだ状態で、`mode` パラメータなしでモード選択画面を開いたとき
- **THEN** Mode D が選択された状態で表示される

#### Scenario: URL の指定が優先される
- **WHEN** 保存済みモードが D のまま `?mode=A` でモード選択画面を開いたとき
- **THEN** Mode A が選択された状態で表示される

#### Scenario: 保存値がない
- **WHEN** 保存値も `mode` パラメータもないとき
- **THEN** Mode B が選択された状態で表示される

### Requirement: Mode A の出題形式と正誤判定
システムは、Mode A で市区町村名を 1 つ提示し、利用者が日本地図で都道府県をタップして選ぶ形式で出題しなければならない (SHALL)。タップは選択のトグルであり、確定は選択数が正解の県数に一致するまで有効にしてはならない (SHALL)。正解は、選んだ都道府県の集合が、その名前を持つ市区町村が実在する都道府県の集合と過不足なく一致するときだけとしなければならない (SHALL)。正解の県集合は設定した出題範囲や難易度で絞らず、マスタ全体で同名の市区町村が属するすべての都道府県としなければならない (SHALL)。Mode A に時間制限はない。

#### Scenario: 同名市の全県を選ぶ
- **WHEN** 伊達市（北海道・福島県）が出題され、北海道と福島県の両方を選んで確定したとき
- **THEN** 正解になる

#### Scenario: 一部の県だけを選ぶ
- **WHEN** 伊達市が出題され、北海道だけを選んでいるとき
- **THEN** 確定は有効にならない

#### Scenario: 余分な県を含める
- **WHEN** 伊達市が出題され、北海道・福島県・青森県を選んで確定したとき
- **THEN** 不正解になる

#### Scenario: 出題範囲外の県も正解に含まれる
- **WHEN** 出題範囲を「関東」にして、関東と他地方の両方に存在する同名市が出題されたとき
- **THEN** 正解の県集合には関東以外の該当県も含まれる

### Requirement: Mode B の出題形式
システムは、Mode B で市区町村名を提示し、所属する都道府県を 4 択で答える形式で出題しなければならない (SHALL)。誤答の 3 択は、出題範囲に含まれる都道府県が 4 つ以上あるときはその中から、4 つ未満のときは全 47 都道府県の中から、正解の県を除いて無作為に選ばなければならない (SHALL)。回答前の問題カードには難易度バッジを表示しなければならない (SHALL)。

#### Scenario: 地方を絞った出題の選択肢
- **WHEN** 出題範囲を「近畿」（7 府県）にして Mode B を出題したとき
- **THEN** 4 つの選択肢はすべて近畿の府県になり、正解の県を 1 つ含む

#### Scenario: 都道府県が少ない地方
- **WHEN** 出題範囲を「北海道」にして Mode B を出題しようとしたとき
- **THEN** 設定画面で 2 県以上の地域が必要である旨が表示され、スタートできない（出題範囲の可否は「出題範囲の種類とモード別の可否」を参照）

### Requirement: Mode C の出題形式
システムは、Mode C で都道府県名を提示し、その県に実在する市区町村を 4 択で答える形式で出題しなければならない (SHALL)。回答前の問題カードには Mode B と同じく難易度バッジを表示しなければならない (SHALL)。誤答は、正解と別の都道府県に属し、かつ正解の県に同名の市区町村が存在しない市区町村名から 3 つ選ばなければならない (SHALL)。誤答は設定画面で選んだ難易度に属するものを優先し、出題範囲の都道府県が 4 つ以上ならその範囲内を先に探さなければならない (SHALL)。候補が 3 つに満たないときは、順に、出題範囲の制限を外して難易度を保つ、難易度の制限も外して全国から補う、の順で補わなければならない (SHALL)。誤答の名前は互いに重複させてはならない (SHALL)。

#### Scenario: 同名市が誤答に混ざらない
- **WHEN** 北海道の伊達市が正解の問題で誤答を選ぶとき
- **THEN** 福島県の伊達市は誤答に選ばれない

#### Scenario: 候補が足りない
- **WHEN** 難易度と地方の条件を満たす誤答候補が 3 つ未満のとき
- **THEN** 出題範囲の制限、次に難易度の制限を外して誤答を補う

### Requirement: Mode D の出題形式と正誤判定
システムは、Mode D で市区町村名と所属都道府県を提示し、その都道府県の地図上で該当の市区町村をタップして答える形式で出題しなければならない (SHALL)。地図は出題された都道府県の市区町村をコード単位の領域として個別にタップできなければならず、同じ表示名の複数コードを 1 つの領域にまとめてはならない (SHALL)。正解は、タップした領域のコードが出題コードと完全に一致するときだけとし、同名・同市の別コード（政令市の他の区など）のタップを正解にしてはならない (SHALL)。回答は 1 回だけで、タップ後は正解と誤ってタップした領域を色分けして示さなければならない (SHALL)。

#### Scenario: 正しい区をタップする
- **WHEN** 札幌市中央区（01101）が出題され、01101 の領域をタップしたとき
- **THEN** 正解になる

#### Scenario: 同じ市の別の区をタップする
- **WHEN** 札幌市中央区（01101）が出題され、札幌市北区（01102）の領域をタップしたとき
- **THEN** 不正解になり、01102 が誤り、01101 が正解として色分けされる

### Requirement: Mode D の制限時間と地図読み込み失敗
システムは、Mode D の各問に 30 秒の制限時間を設け、時間切れを不正解として記録し、正解の領域を示さなければならない (SHALL)。時間切れの回答時間は 30,000ms として保存しなければならない (SHALL)。地図の読み込みに失敗したときは、その問題を 4 択（Mode C と同じ形式。次の問題では再び地図を試す）に切り替えなければならない (SHALL)。切り替え後は制限時間を適用してはならず (SHALL NOT)、4 択の回答は `mode = 'C'` として保存しなければならない (SHALL)。

#### Scenario: 時間切れ
- **WHEN** Mode D の問題で 30 秒以内にタップしなかったとき
- **THEN** 不正解として保存され、連続正解は途切れ、正解の領域が示される

#### Scenario: 地図の読み込み失敗
- **WHEN** Mode D の問題で地図データまたは Google Maps の読み込みに失敗したとき
- **THEN** 同じ問題が 4 択で表示され、その回答は Mode C の結果として保存される

### Requirement: Mode D は政令市の区を区名で表示する
システムは、Mode D の出題・フィードバック・結果一覧・市区町村選択ダイアログでは、政令市の区を区名入り（例: 札幌市中央区）で、読み仮名も区単位で表示しなければならない (SHALL)。東京 23 区は保存名のまま表示しなければならない (SHALL)。Mode A / B / C では政令市を保存名（親市名。例: 札幌市）のまま表示しなければならない (SHALL)。

#### Scenario: Mode D の表示名
- **WHEN** Mode D で京都市左京区（26103）が出題されたとき
- **THEN** 出題・フィードバック・結果一覧のいずれも「京都市左京区」と、その読み仮名で表示される

#### Scenario: Mode B の表示名
- **WHEN** Mode B で同じコードの市が出題されたとき
- **THEN** 「京都市」と表示される

### Requirement: 出題範囲の種類とモード別の可否
システムは、出題範囲として「地方（複数選択可。全国は他の地方と排他で、選択をすべて外すと全国に戻る）」と「都道府県（1 つ）」を扱わなければならない (SHALL)。都道府県指定は Mode C と Mode D だけで有効とし、設定画面で地方と都道府県を切り替える操作は Mode D だけに出さなければならない (SHALL)。Mode A / B は、地方を選んだ結果の対象が 1 県だけ（北海道のみ）のとき、および都道府県指定のときは出題範囲として成立させてはならず (SHALL NOT)、設定画面にその旨を示してスタートを無効にしなければならない (SHALL)。URL の範囲指定（`scope`・`pref`・`prefecture`・`region`・`regions`・`codes`）は設定画面の初期値として解釈し、Mode A / B に都道府県指定が来たときは全国の地方指定に置き換え、存在しない都道府県名は東京都に置き換えなければならない (SHALL)。

#### Scenario: Mode A で北海道だけを選ぶ
- **WHEN** Mode A の出題地域を「北海道」だけにしたとき
- **THEN** 2 県以上の地域が必要である旨が表示され、スタートは無効になる

#### Scenario: Mode D で単一の道県を選ぶ
- **WHEN** Mode D の出題範囲を「都道府県で選ぶ」にして北海道を選んだとき
- **THEN** スタートできる

#### Scenario: Mode A に都道府県指定の URL が来る
- **WHEN** `/quiz/municipality/a?pref=大阪府` を開いたとき
- **THEN** 出題範囲は全国の地方指定になる

### Requirement: Mode D のカスタム出題プール
システムは、都道府県指定のときに、その県の市区町村を個別に選ぶ出題プールを指定できなければならない (SHALL)。この指定は Mode D の設定画面から行い、Mode C では URL の `codes` でだけ指定できる。選択ダイアログは、区名・よみがなで絞り込む検索、すべて選択・すべて解除、各市区町村の難易度と制覇済みの印を備えなければならない (SHALL)。全件を選んだ状態は個別指定なし（県内すべて）として扱い、1 件も選ばなければ出題対象は 0 件でスタートできなくしなければならない (SHALL)。個別指定のコードのうち、その県に属さないものは取り除かなければならない (SHALL)。難易度・未クリア優先・苦手優先・制覇進捗は、個別指定したプールを母集団として適用しなければならない (SHALL)。

Mode D の範囲指定は URL のクエリ文字列に反映し、localStorage（`geodojo_last_mode_d_scope`）にも保存しなければならない (SHALL)。範囲指定を持たない URL で Mode D を開いたときは保存済みの範囲を復元しなければならず、破損した保存値は無視しなければならない (SHALL)。おすすめ（`source=recommend`）から開いたセッションは、保存済みの範囲を復元も上書きもしてはならない (SHALL NOT)。「もう一度」と設定画面への復帰では範囲指定を保持しなければならない (SHALL)。

#### Scenario: 一部の区だけで練習する
- **WHEN** Mode D で東京都を選び、市区町村を 5 件だけ選んでスタートしたとき
- **THEN** 出題はその 5 件の中からだけ行われ、制覇進捗の母数もその 5 件になる

#### Scenario: 全件を選び直す
- **WHEN** 選択ダイアログで県内のすべてを選んで決定したとき
- **THEN** 個別指定なし（県内すべて）になる

#### Scenario: 保存した範囲の復元
- **WHEN** 範囲指定のない URL で Mode D の設定画面を開き、保存済みの範囲があるとき
- **THEN** 保存済みの範囲が復元される

#### Scenario: おすすめ経由では保存を上書きしない
- **WHEN** `source=recommend` で Mode D を開いて範囲が変わったとき
- **THEN** localStorage の保存済み範囲は更新されない

### Requirement: 難易度フィルタと出題数
システムは、難易度（入門・中級・上級・達人）を複数選択で絞り込めるようにし、既定は入門と中級にしなければならない (SHALL)。難易度が未設定の市区町村は、絞り込みの対象から外さなければならない (SHALL)。出題数は 10 / 20 / 30 問から選べ、既定は 10 問としなければならない (SHALL)。出題プールが出題数より小さいときは、プールの全件を出題し、その件数だけで出題される旨を設定画面に示さなければならない (SHALL)。難易度を 1 つも選んでいない、またはプールが 0 件のときはスタートできてはならない (SHALL NOT)。URL の `difficulty` / `difficulties` / `count` は設定の初期値として使い、count は 10・20・30 以外のとき 10 としなければならない (SHALL)。

#### Scenario: プールが出題数より小さい
- **WHEN** 条件に合う出題単位が 7 件で出題数が 10 問のとき
- **THEN** 「該当 7 件のみ — 全 7 問で出題されます」と表示され、7 問で出題される

#### Scenario: 難易度をすべて外す
- **WHEN** 難易度の選択をすべて外したとき
- **THEN** 「難易度を選択してください」と表示され、スタートは無効になる

### Requirement: テキスト形式モードの除外と出題単位
システムは、Mode A / B / C の出題プールから、東京 23 区（東京都の「区」）と、都道府県名と同一とみなせる市区町村（都道府県名の末尾の都道府県を除いた名前と、市区町村名の末尾の 1 文字（市区町村）を除いた名前が一致するもの。例: 青森市、大阪市、京都市）を除かなければならない (SHALL)。Mode D はこれらを除外せず、マスタの全件を対象にしなければならない (SHALL)。

出題の単位は次のとおりとし、同じ単位は 1 セッションに 1 回しか出題してはならない (SHALL NOT)。

- Mode A: 市区町村名（都道府県をまたいで同名を 1 問に集約）
- Mode B / C: 都道府県と市区町村名の組（政令市は区をまとめて 1 問）
- Mode D: 市区町村コード（政令市の区は区ごとに別の問）

#### Scenario: 同名除外
- **WHEN** Mode B で全国を対象に出題プールを作るとき
- **THEN** 青森市（青森県）と大阪市（大阪府）は含まれない

#### Scenario: Mode D は除外しない
- **WHEN** Mode D で東京都を対象に出題プールを作るとき
- **THEN** 東京 23 区が含まれる

#### Scenario: 政令市の集約
- **WHEN** Mode B で札幌市（10 区）を含むプールから出題するとき
- **THEN** 札幌市は 1 問としてだけ出題される

#### Scenario: Mode D は区ごと
- **WHEN** Mode D で札幌市を含むプールから出題するとき
- **THEN** 札幌市の各区が別々の問として出題されうる

### Requirement: 未クリア優先と苦手優先の出題抽出
システムは、既定でオンの「未クリア優先出題」とオフの「苦手優先モード」に従って出題を抽出しなければならない (SHALL)。未クリア優先では、そのモードで 1 度も正解していない出題単位を先に抽出し、出題数に足りないときだけクリア済みの単位で補い、出題順は未クリアが先でクリア済みが後にならなければならない (SHALL)。クリア済みの判定は、出題単位に属するコードのいずれかが、そのモードで正解として保存されているかどうかとしなければならない (SHALL)。苦手優先では、過去の誤答率に基づく重み付き抽出をしなければならない (SHALL)。重みは誤答率に 0.1 を足した値（下限 0.01）とし、出題単位が複数コードを持つときは誤答率が最大のコードを使わなければならない (SHALL)。誤答率は全モードの結果をコード単位で集計したものである。両方がオンのときは、未クリア群とクリア済み群のそれぞれの中で重み付き抽出を行わなければならない (SHALL)。条件によらず、抽出は出題数を超えず、同一の出題単位を重複させてはならない (SHALL NOT)。

#### Scenario: 未クリアが足りる
- **WHEN** 未クリアの出題単位が出題数以上あるとき
- **THEN** 出題はすべて未クリアの単位になる

#### Scenario: 未クリアが足りない
- **WHEN** 未クリアが 4 件で出題数が 10 問のとき
- **THEN** 先頭 4 問が未クリア、残り 6 問がクリア済みから補われる

#### Scenario: 政令市の別の区でクリア済み
- **WHEN** Mode B で札幌市のどれかの区のコードが Mode B で正解として保存されているとき
- **THEN** 札幌市は Mode B ではクリア済みの単位として扱われる

#### Scenario: 苦手優先
- **WHEN** 苦手優先をオンにして、誤答率の高い市区町村と全問正解の市区町村が混在するプールから出題するとき
- **THEN** 誤答率の高い市区町村ほど選ばれやすくなる

### Requirement: 回答直後のフィードバックの内容
システムは、回答の直後に、正誤・連続正解数に加えて、正解の市区町村の名前、読み仮名、所属都道府県、難易度、人口をフィードバックとして示さなければならない (SHALL)。人口は 10,000 人以上のとき「約○.○万人」、10,000 人未満のとき「約○,○○○人」と表記し、欠損・0 以下のときは人口を表示してはならない (SHALL NOT)。難易度は、Mode B / C / D では出題された市区町村のもの、Mode A では対象の市区町村群のうち最も難しいものを示さなければならない (SHALL)。Mode D の名前と読み仮名は区単位で示し、人口は出題された区自身のものを示さなければならない (SHALL)。フィードバックの表示中にも、支援技術に向けて正否・名前・読み・難易度・人口が読み上げられなければならない (SHALL)。

#### Scenario: Mode D の人口
- **WHEN** Mode D で札幌市中央区が出題され、回答したとき
- **THEN** 人口は札幌市全体ではなく中央区自身のものが示される

#### Scenario: 人口の表記
- **WHEN** 人口が 275 万 4 千人の市の回答直後のとき
- **THEN** 「約275.4万人」と表示される

#### Scenario: 人口が欠損している
- **WHEN** 出題された市区町村の人口がマスタにないとき
- **THEN** 人口は表示されず、他の情報は表示される

### Requirement: 政令市の人口合算と多県同名市の併記
システムは、Mode B / C で、同じ県に同名の複数コード（政令市の区）を持つ市が出題されたとき、人口をその全コードの合計として示さなければならない (SHALL)。合計の対象コードのどれか 1 つでも人口が欠損・0 以下のときは、不完全な合計を示さず人口を表示してはならない (SHALL NOT)。Mode A で複数の県に同名の市区町村があるときは、県をまたいで人口を合算せず、県ごとの内訳（県名・読み仮名・人口）を併記しなければならない (SHALL)。内訳の人口は、その県内に同名の複数コード（政令市の区）があるときはそれらの合計とする。併記は、同じ県の複数コードを 1 件に畳んで県ごとに 1 件とし、カードには最大 4 県までの内訳を表示しなければならない (SHALL)。Mode D は出題された区自身の人口を示さなければならない (SHALL)。人口は 1 万人以上なら「約○.○万人」、1 万人未満なら「約○,○○○人」と表記し、人口が無いか 0 以下なら表示してはならない (SHALL NOT)。

#### Scenario: 政令市の合算
- **WHEN** Mode B で全区の人口が揃っている政令市が出題されたとき
- **THEN** 回答直後に全区の合計人口が示される

#### Scenario: 一部の区の人口が欠損
- **WHEN** 政令市の区のうち 1 つの人口がマスタにないとき
- **THEN** 市の人口は表示されない

#### Scenario: 池田町（4 県）
- **WHEN** Mode A で池田町（北海道・福井県・長野県・岐阜県）が出題され、回答したとき
- **THEN** 4 県それぞれの県名・読み仮名・人口が併記され、人口は合算されない

### Requirement: 結果の保存
システムは、1 問の回答ごとに `municipality_quiz_results` へ結果を保存しなければならない (SHALL)。保存の単位は次のとおりとする。

- Mode A: 同名市は 1 問で出題するが、都道府県ごとに代表 1 コードを選び、県ごとに 1 行を保存する（政令市の区の数だけ行を増やさない）。1 バッチの行数は 1〜10。
- Mode B / C / D: 出題された 1 コードを 1 行で保存する。

1 問分の保存は 1 回のサーバー呼び出しと 1 つのトランザクションで行い、同じトランザクションで SRS の更新も行わなければならない (SHALL)。どちらかが失敗したときは、結果の行も SRS も保存されてはならない (SHALL NOT)。保存する `isCorrect` は 1 問に対する採点結果で、バッチ内のすべての行で同じにしなければならない (SHALL)。回答時間は 0 以上で PostgreSQL の integer に収まる有限の数だけ四捨五入して保存し、範囲外や不正な値は null としなければならない (SHALL)。回答時刻はサーバー側で決めなければならない (SHALL)。

サーバーは、保存の前に次を検証し、満たさなければ保存せずに失敗としなければならない (SHALL)。

- 認証済みであること、およびレート制限（1 ユーザーあたり 1 分 60 回）を超えていないこと
- バッチが空でなく、すべての行のモードが同じ A〜D のいずれかで、`isCorrect` が真偽値であること
- すべてのコードが `municipality_master` に存在すること（検証の根拠は DB であり、`public/` のファイルを実行時に読んではならない (SHALL NOT)）
- Mode A: コードの重複がなく、同名で、入力の名前がマスタの名前と一致し、1 県につき 1 コードで、県の集合が「同名で、都道府県名と同一とみなされず、東京 23 区でもない」県の集合と一致すること
- Mode B / C / D: ちょうど 1 行であること

#### Scenario: Mode A の同名市の保存
- **WHEN** Mode A で伊達市（北海道・福島県）に回答したとき
- **THEN** 北海道と福島県の 2 行が同じ正誤と回答時刻で 1 つのトランザクションに保存される

#### Scenario: 政令市は 1 県 1 行
- **WHEN** Mode A で札幌市（10 区のコード）に回答したとき
- **THEN** 保存されるのは北海道の代表 1 コードの 1 行だけである

#### Scenario: マスタにないコード
- **WHEN** マスタに存在しないコードを含むバッチが送られたとき
- **THEN** 保存は拒否され、1 行も保存されない

#### Scenario: SRS の更新に失敗する
- **WHEN** 結果の行を挿入した後で SRS の更新が失敗したとき
- **THEN** トランザクション全体が取り消され、結果の行も残らない

#### Scenario: レート制限
- **WHEN** 同一ユーザーが 1 分間に 61 回目の保存を要求したとき
- **THEN** 保存は拒否される

### Requirement: 保存の失敗をサイレントにしない
システムは、結果の保存に失敗したとき、サーバーとクライアントの両方で原因を `console.error` に残さなければならない (SHALL)。サーバーはログを残したうえでエラーを再 throw しなければならない (SHALL)。クライアントは失敗した問題を「保存されなかった」として記録し（以後のおすすめ履歴に加えない）、出題の進行は止めてはならず (SHALL NOT)、その問題の正誤は画面上の結果に含めなければならない (SHALL)。保存の完了を待っている間に次へ進む操作が行われたときは、保存の完了後に待ち時間なしで次へ進まなければならない (SHALL)。

#### Scenario: 保存が失敗する
- **WHEN** 1 問の結果の保存がサーバーで失敗したとき
- **THEN** サーバーとクライアントの両方にエラーログが残り、クイズは次の問題へ進み、その問題は結果画面の件数に含まれる

#### Scenario: 中断
- **WHEN** 保存の完了前に中断したとき
- **THEN** 進行中の保存の完了を待ってから設定画面へ戻る

### Requirement: 表示件数は 1 問 1 件に正規化する
システムは、結果画面・進捗・完了件数・正答数・苦手一覧に使う結果を、保存した行数ではなく 1 問につき 1 件に正規化しなければならない (SHALL)。Mode A で複数県を持つ同名市は、県名を「・」で連結した 1 件にし、読み仮名が県ごとに異なるときは「県: 読み」を「 / 」で連結して示さなければならない (SHALL)。Mode D の結果は区名・区の読みで示し、Mode A / B / C は保存名で示さなければならない (SHALL)。

#### Scenario: 21 行を保存しても 19 問
- **WHEN** 19 問のうち 2 問が 2 県にまたがる同名市で、保存した行が合計 21 行になったとき
- **THEN** 結果画面の完了件数は 19 問、正答数は 19 問のうち正解した数になる

#### Scenario: 読み仮名が県ごとに違う
- **WHEN** 同名だが県ごとに読みが違う市が出題されたとき
- **THEN** 結果一覧には「北海道: 〜 / 福島県: 〜」の形で併記される

### Requirement: 制覇進捗とその母数
システムは、設定画面に現在の設定（モード・出題範囲・難易度）に対する制覇進捗を「クリア数 / 母数 問クリア (○%)」で示さなければならない (SHALL)。母数は、現在の出題プールに含まれる出題単位（Mode A は市区町村名、Mode B / C は県と市区町村名の組、Mode D はコード）の数でなければならず (SHALL)、Mode A / B / C では東京 23 区と都道府県名と同一とみなされる市区町村を含めてはならない (SHALL NOT)。クリア数は、出題単位に属するコードのいずれかが、そのモードで正解として 1 度でも保存されている単位の数とし、後の誤答で取り消してはならない (SHALL NOT)。他のモードの正解は数えてはならない (SHALL NOT)。割合は四捨五入し、全単位をクリアしたときだけ 100% とし、それ未満は最大 99% としなければならない (SHALL)。全単位をクリアしたときは「制覇済み！」を表示しなければならない (SHALL)。取得中は読み込み表示、失敗時は再試行を提示しなければならず (SHALL)、母数が 0 のときは進捗を表示してはならない (SHALL NOT)。

#### Scenario: 99% で止まる
- **WHEN** 母数 300 のうち 299 件をクリアしたとき
- **THEN** 割合は 99% と表示され、「制覇済み！」は出ない

#### Scenario: 他モードの正解は数えない
- **WHEN** Mode B で正解した市区町村を、Mode D の設定画面で見るとき
- **THEN** Mode D のクリア数には含まれない

#### Scenario: 東京 23 区は Mode A の母数に入らない
- **WHEN** 関東を対象に Mode A の設定画面を開いたとき
- **THEN** 母数に東京 23 区の区は含まれない

### Requirement: スタートの可否と設定画面の状態
システムは、マスタの読み込み、必要な問い合わせの完了、出題範囲の成立、難易度の選択、プールの存在がすべて満たされるまで、スタートを無効にしなければならない (SHALL)。未クリア優先がオンのときはクリア済みコードの取得が、苦手優先がオンのときは苦手データの取得が、成功して再取得中でもオフライン中断中でもない状態になるまでスタートさせてはならない (SHALL NOT)。必要な取得が失敗したときは、スタートのボタンに失敗を示し、再試行できなければならない (SHALL)。ボタンの表示は「データ読み込み中...」「データ取得に失敗しました（再試行してください）」「地域を追加してください」「難易度を選択してください」「該当する市区町村なし — 条件を変更してください」「スタート」のいずれかとし、上の順に優先して示さなければならない (SHALL)。

#### Scenario: クリア済みコードの取得中
- **WHEN** 未クリア優先がオンで、クリア済みコードの取得が終わっていないとき
- **THEN** スタートは無効で「データ読み込み中...」と表示される

#### Scenario: 苦手データの取得失敗
- **WHEN** 苦手優先がオンで苦手データの取得に失敗したとき
- **THEN** スタートは無効で、再試行のリンクが表示される

### Requirement: 結果画面と再挑戦
システムは、全問の回答後に正解数と問題数、および誤答した市区町村の一覧（名前と「読み / 都道府県」）を示さなければならない (SHALL)。「もう一度」は、同じ設定で、クリア済みコードと苦手データを最新に取り直してから新しい問題を作り直さなければならない (SHALL)。取り直しに失敗したときは、新しい出題を始めずにエラーを示さなければならない (SHALL)。「設定に戻る」は同じ設定の設定画面へ戻らなければならない (SHALL)。完了と中断のどちらでも、そのモードのクリア済みコード、苦手データ、ダッシュボード、おすすめのキャッシュを無効にして、次の表示で最新にしなければならない (SHALL)。結果画面の共通部分は `quiz-session` を、おすすめ経由の結果画面の操作は `recommendation` を参照する。

#### Scenario: もう一度
- **WHEN** 結果画面で「もう一度」を押したとき
- **THEN** 直前の回答を反映したクリア済みコードで、同じ設定の新しい問題が出題される

#### Scenario: 取り直しの失敗
- **WHEN** 「もう一度」の最新データの取得に失敗したとき
- **THEN** 出題は始まらず、「最新データの取得に失敗しました。再試行してください。」が表示される
