# 逆引き制覇の非対称クレジット

日付: 2026-08-30  
状態: 設計合意（実装前）

## 問題

モードA（逆引き地図）とモードB（逆引き4択）は、どちらも「市区町村名 → 都道府県」である。違いは想起（47都道府県の地図）と再認（4択）だけで、知識としてはほぼ同じ。

一方、全国制覇の分母は A（名前ユニーク）+ B（名前×県）+ C（名前×県）+ D（コード）である。Aで全部当ててもB枠は空のままなので、同じ知識を二周しないとゲージが進まない。

A正解をBにも加算するだけだと、全体ゲージではAの1問で分子が2枠動く。C/Dは1枠のままなので、地図が制覇率の最短ルートになる。

## 決定

1. 全体制覇の逆引きは **1枠**。単位はBと同じ `(name, prefecture)`。AまたはBの正解でその枠は埋まる。
2. モードB単体のゲージも、同じ `(name, prefecture)` をA正解で埋めてよい（B周回は制覇に必須ではない）。
3. モードA単体は今どおり。B正解では埋まらない。
4. モードC/Dは変えない。
5. SRS（復習カード）は `(municipalityCode, mode)` のまま。A正解でBのdueは消さない。
6. スキーマ変更・履歴バックフィルSQLは不要。集計とおすすめの解釈だけ変える。既存のA正解は、デプロイ後すぐB枠・全体逆引き枠に効く。

## 制覇の定義

同一名除外（県名と市区町村名が一致する「青森市」等）は、現行どおりA/B/Cの分母・分子から外す。

| 画面のフィルタ | 分母 | 分子（クリア） |
|---|---|---|
| 全体 | 逆引き `(name, pref)` + C `(name, pref)` + D（マスタ全件） | 逆引き: その組をAまたはBで正解したことがある。C/Dは現行どおり当該モードの正解 |
| A | `COUNT(DISTINCT name)`（現行） | Aの正解のみ（現行） |
| B | `(name, pref)`（現行） | Bの正解 **または** 同じ `(name, pref)` のA正解 |
| C | `(name, pref)`（現行） | Cの正解のみ |
| D | マスタ全件（現行） | Dの正解のみ |

現行の全体分母は `A名数 + (B/C組数)×2 + D件数`。新分母は **`(B/C組数)×2 + D件数`**（A名数を足さない）。逆引きの組数はBの分母と同じ。

Aは同名を1問にまとめ、保存は県ごと（伊達市なら北海道と福島で別行）。全体・Bの `(name, pref)` クレジットは、その保存行の県にだけ効く。Aで不正解なら、その問の保存行はクレジットしない。

設定画面の制覇進捗（`computePoolStats`）と、難易度別ゲージ・おすすめの90%ステップアップも、上表と同じ定義にする。画面によって「クリア」が食い違わないこと。

## 説明文

A由来でBや全体の逆引きが埋まることは、見えないとバグに見える。長くせず1行置く。

- ダッシュボード「全国制覇」（フィルタが全体のとき）
- 設定画面の制覇進捗（モードBのとき）

- 全体: 「逆引き地図（A）と4択（B）は同じ逆引き枠として1回だけ数えます。」
- モードB: 「逆引き地図（A）で正解した市区町村は、4択（B）でも制覇済みになります。」

B単体バーがAだけで100%になり得る点は、B側の1行で回収する。

## おすすめ

制覇と食い違うと、ゲージは埋まっているのにBを未挑戦として出す。

- コールドスタート（回答が少ない）は今どおりモードB。4択が入口。
- AがFit Zoneに入っているときは、対象モードをBにしない。探索・未開拓（novelty / underexplored）に加え、難易度進行のモード切替（`change-mode` / `nextMode`）も含む。例外なし。
- BだけやってA未挑戦のときは、ときどきAを出してよい。易しい方から難しい方への一段だけ。逆（A安定後にBへ戻す注入）はしない。
- 穴埋め（coverage）の「未プレイ」は、逆引きについては **AでもBでもまだ正解していない** `(name, pref)`。Aで埋まっている組をB用に出さない。
- 難易度ステップアップの制覇率90%は、上表のクレジット後の coverage を使う。BセルはA正解を含めて計算する。
- 通常おすすめのモード選択と、復習キューは別。SRSは触らない。

コールドスタート文言や「モードBは未挑戦」は、上の注入をやめたあとも出さない。

## 実装の当たり（合意後）

- 分母: `lib/db/queries/sql-helpers.ts` の `getMasterPoolSize('all')` からA名数を外す。
- 分子: 全体の逆引きは `mode IN ('A','B')` で `(name, pref)` を DISTINCT。B単体の `getClearedDistinctSql` もA行を含める（モードフィルタをBのみにしない）。
- ダッシュボード固有の再実装も同じ定義にする。`lib/db/queries/dashboard.ts` の `fetchCurrentSummaryCounts` / `fetchPrevSummaryCounts`、難易度・推移向けの `calculateDiffTotals` / `getCompletionEntryKey` をヘルパーと食い違わせない。
- Bフィルタの外側WHERE: `getCompletionTrendData` / `getDifficultyProgressData` / `getCompletionByModeData` が `mode = 'B'` だけで行を落とすと、DISTINCT側を直してもA正解がB表示に入らない。B表示ではA/B両方の行を残す。
- クライアント側プール進捗: `lib/quiz/sampling.ts` のBクリア判定にA正解集合を渡す。
- Aプレイ後のキャッシュ: `clearedCodes('A')` だけ無効化すると、B画面が古い未制覇のまま残る。Bキーも無効化するか、A/B共通キーにする。回答完了時に推薦キャッシュ（`recommendation`）も無効化する。結果画面から「今日のおすすめ」へ戻る導線を回帰に含める。
- おすすめ: `computeCellCoverages` のBセル、`engine.ts` の underexploredModes、`evaluateProgression` の `nextMode`（AがFit ZoneならBを対象にしない）、coverage の played 判定。
- 回帰テスト: 分母がA+B二重にならないこと、A正解だけでB/全体逆引きが埋まること（Bフィルタの推移・難易度・完了数を含む）、B正解ではAゲージが動かないこと、C/D非影響、ダッシュボード各面が同じ分子であること、おすすめがA安定後にBへ戻さないこと（進行のモード切替含む）、A直後にBキャッシュが古くないこと、回答完了後におすすめキャッシュが古くないこと。
